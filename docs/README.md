## 新增文档放哪

| 内容类型 | 目录 |
|---|---|
| 架构、外链规范、数据源结构 | `01-架构与规范/` |
| 部署、安装、升级 | `02-部署运维/` |
| 评分类功能 | `03-评分/` |
| 抗感染相关 | `04-抗感染/` |
| 临床监测类 | `05-临床监测/` |
| 质控指标与规则 | `06-质控/` |
| 工作台、驾驶舱等 | `07-工作台与其他/` |

文件名格式 `NN-主题-类型.md`，类型用 `-产品设计` / `-实施方案` / `-改造方案` / `-口径方案`。

新增后同步更新三处：

1. 本文件
2. [`../README.md`](../README.md) 的「文档」段（挑重点补，不必全列）
3. 文档内交叉引用路径（分类化后形如 `docs/05-临床监测/20-xxx.md`）

## 交付包里的文档

外发包**默认只含三份**（`02-外链传参规范` / `03-部署说明` / `04-安装部署手册`），且在包内**平铺**到 `docs/` 下、不带分类目录 —— 部署方不需要分类层级，`install.sh` 的报错提示也按扁平路径写。

需要带全部文档时用 `tools/build-delivery.ps1 -KeepDocs`（内部交付用，会带上完整分类目录结构）。
