# 医生系统（zing-doctor）架构设计

> 版本：v23.1.x · 更新于 2026-09-11
> 定位：ICU 临床信息系统中「抗菌药物分析」功能模块的独立医生系统。已由第一维度扩展为**五个抗菌药物管理维度 + 四个临床辅助模块**。

## 1. 总体架构

```
┌──────────────────────────────────────────────────────────────────────────┐
│  前端（Vue3 + Element Plus，Nginx 托管，history 路由，/page/{pageCode}）      │
│  维度一 疑似感染患者列表 / 经验性抗感染决策                                    │
│  维度二 PK/PD 剂量优化   · 维度三 DDD 使用强度（+明细/配置）                    │
│  维度四 细菌培养监测（+明细/配置）· 维度五 医生交班览表                         │
│  辅助 脓毒症集束化 / APACHE II 评分（+总览）/ ARDS 监测 / 出科统计 / 词库配置    │
└───────────────┬──────────────────────────────────────┬───────────────────┘
                │ /api/**（携带外链鉴权请求头）           │ /entry/{pageCode}（外链入口，302）
┌───────────────▼──────────────────────────────────────▼───────────────────┐
│  后端（Spring Boot 2.7，Java 8，端口 8081）                                  │
│  ExternalLinkInterceptor → 外链校验（签名模式 / ICU 明文模式）                 │
│  模块：antibiotic（维度一~四）· sepsis · apache2 · ards · handover          │
│        external（外链机制）· icu（ICU 数据适配层，接口契约）                    │

┌───────▼─────────────┐     ┌───────────▼──────────────────────────────┐
│ zing_doctor_db_prod  │     │ zing_icu_db_prod（ICU 系统库，只读）          │
│ 医生系统自有数据：     │     │ 患者/诊断/医嘱/检验/微生物/监护/职工           │
```

## 2. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Spring Boot 2.7.18 + Java 8 | 与服务器 ICU 系统 Java 栈一致 |
| ORM | MyBatis-Plus 3.5.5 + dynamic-datasource 3.6.1 | 多数据源注解切换 `@DS("icu")` |
| 前端 | Vue 3 + Vite 5 + Element Plus + vue-router 4 + ECharts | history 路由，支持每页面外链直达 |
| 数据库 | 达梦 DM8 | 主库 `zing_doctor_db_prod`，只读库 `zing_icu_db_prod`；驱动随 `lib/` 打包 |
| 部署 | Docker / docker-compose | 后端 JRE8 容器，前端 Nginx 容器；内网可降级 java -jar + nginx |

## 4. 双数据源

- 主库 `doctor`：写入医生系统业务数据（决策记录、方案日志、外链访问日志、页面配置、各维度配置与业务记录、评分/交班记录）。
- 只读库 `icu`：`read-only: true`，仅用于读取 ICU 系统患者/诊断/医嘱/检验/微生物/监护数据。
- 切换方式：Mapper 或 Service 方法上加 `@DS("icu")`。
- ICU 数据提供方式通过 `zing.doctor.icu-data-provider` 切换：
  - `mock`（默认）：内置示例患者打通流程，无需真实 ICU 库；
  - `sql`：`SqlIcuPatientServiceImpl` 基于 ICU 真实表结构只读查询 `zing_icu_db_prod`，接口契约不变；SQL 遵循达梦方言（双引号小写标识符、`SYSDATE-n`、`ROWNUM`），数值/类型过滤尽量放 Java 端规避 CAST 报错。

## 5. 外链免登录（双模式）

| 模式 | URL 形态 | 适用 | 时效 |
|---|---|---|---|
| ICU 明文模式 | `/entry/{pageCode}?extToken={静态密钥}&业务参数` | ICU 系统外链模板只做 `${}` 占位替换、不算 HMAC | 无过期，依赖内网 + 静态密钥 |
| 签名模式 | `/entry/{pageCode}?expire={ts}&sign={hmac}&业务参数` | 可动态签名的调用方 | 默认 10 分钟 |

- 签名算法：`canonical = pageCode=..&expire=..&其余参数按 key 字典序 k=v 连接`，`sign = hex(HmacSHA256(secret, canonical))`；校验采用常量时间比较防时序攻击。
- 链路：外部系统 → `/entry` 校验 → 记录访问日志 → 302 到 `/page/{pageCode}?...` → 前端捕获上下文存 sessionStorage → `/api/**` 携带 `X-External-PageCode` 及 `X-External-Token` 或 `X-External-Expire`/`X-External-Sign` → `ExternalLinkInterceptor` 复算校验。
- 页面需在 `zing_page_config` 注册方可外链；可选 `allow-page-codes` 白名单。详见 `docs/02-外链传参规范.md`。

## 6. 各维度数据流

1. **维度一 经验性抗感染决策**：ICU 适配层取评估数据 → 规则引擎按「脓毒性休克 / 感染部位」分层，叠加 MRSA / MDR / 真菌风险生成可解释推荐（依据 SSC 2021 等）→ 医生决策落库 `zing_decision_record` + `zing_advice_log`。
2. **维度二 PK/PD 剂量优化**：肌酐清除率（Cockcroft-Gault）、eGFR、肾功能分级、体重/BMI → 结合 `AbxDrugKnowledge` 输出剂量/延长输注/负荷建议与 TDM 目标。
3. **维度三 DDD 使用强度**：按 `zing_ddd_config` 知识库匹配医嘱，统计使用率、DDDs、药品排名、月度趋势与患者明细。
4. **维度四 细菌培养监测**：从 ICU 检验明细提取培养/药敏结果 → 按 `zing_mdro_config` 分类 → 菌株排名、标本分布、高风险预警。
5. **维度五 交班览表**：按上一完整全天班次聚合在科患者的病情/生命体征/器官支持/出入量/检验异常，支持医生手工填写病情变化。
