## 2. 达梦数据库初始化（在能连达梦的机器上，用 disql 或管理工具）

> **提示**：`install.sh` 会自动完成本步（自动探测 disql / 达梦容器 / JDBC 工具）。
> 以下为手动方式，仅在自动通道全部不可用时使用。

**只初始化一次**，统一用 `SYSDBA` 连接达梦 100.120.1.102:14236，依次执行以下脚本（`03_icu_indexes.sql`、`05_apache2_pdf.sql` 为可选/升级脚本）：

```bash
# 方式一：disql 命令行（服务器装有达梦客户端时）
/opt/dmdbms/bin/disql SYSDBA/Sa_20250815@100.120.1.102:14236
SQL> start /opt/zing-doctor/sql/00_init_user.sql   # 建模式 zing_doctor_db_prod（AUTHORIZATION SYSDBA）
SQL> start /opt/zing-doctor/sql/01_schema.sql      # 建 11 张业务表（SQL 内显式模式前缀）
SQL> start /opt/zing-doctor/sql/02_seed.sql        # 初始化页面注册/DDD/MDRO/词库等种子数据
SQL> start /opt/zing-doctor/sql/03_icu_indexes.sql # （建议）ICU 库只读查询性能索引
SQL> start /opt/zing-doctor/sql/05_apache2_pdf.sql # （升级）APACHE II PDF 列，幂等
SQL> start /opt/zing-doctor/sql/06_abx_drug_dict.sql # 抗菌药物字典表（HIS 同步副本，只执行一次）
SQL> start /opt/zing-doctor/sql/07_sofa.sql        # SOFA 评分建表 + 页面注册 + 配置种子
SQL> start /opt/zing-doctor/sql/08_sofa_p1.sql     # SOFA 页面注册与列注释，幂等
SQL> start /opt/zing-doctor/sql/09_quality.sql     # 质控指标中台建表 + 页面注册，幂等
SQL> exit
```

> 医生系统**统一用 SYSDBA 连接**（与 ICU 系统访问方式一致），通过显式模式前缀访问 `zing_doctor_db_prod` 模式；表不建在 SYSDBA 默认模式下。
> 若服务器无 disql：用**达梦管理工具**（Windows 端 DTS/Manager 连接 100.120.1.102:14236）按上述脚本顺序执行，或让 DBA 代执行。

### 验证建表结果

```sql

SELECT TABLE_NAME FROM ALL_TABLES WHERE OWNER = 'ZING_DOCTOR_DB_PROD';
-- 确认 ICU 模式表可用（SYSDBA 连接）
```

## 4. 一键安装部署（部署机 100.120.1.104）

交付包根目录执行 `install.sh`，**自动完成**：达梦初始化（建表+种子）→ 构建 → 启动 → 输出验证方式。

```bash
cd /opt/zing-doctor        # 部署路径 = 解压路径（脚本不写死路径）
bash install.sh
```

`install.sh` 初始化达梦时自动选择可用通道（顺序尝试）：
1. 本机 disql 客户端；
2. 达梦 Docker 容器内 disql（自动探测 dm8/dameng 容器）；
3. 本机 JDK + 内置 JDBC 初始化工具（`tools/db-init`，复用达梦驱动）。

三个通道都不可用时会打印**手动初始化指引**并退出（见 §2）。重复部署需跳过建表时可加参数：`bash install.sh --skip-db`。

> **幂等说明**：达梦初始化脚本（`00_init_user.sql` / `01_schema.sql` / `02_seed.sql`）已支持重复执行——内置 JDBC 工具（`tools/db-init`）对 `CREATE SCHEMA` / `CREATE TABLE` / `CREATE INDEX` 会先检查对象是否已存在，已存在则跳过；`02_seed.sql` 先 DELETE 再 INSERT。因此同一交付包可直接**重复运行 `./install.sh`** 完成升级/重装，不会因“对象已存在”报错中断。注意：已存在的表**不会重建**（结构变更需手动 DROP 后重跑，或使用 `--skip-db` + 手动执行新脚本）。

### 部署模式自动切换（关键）

`install.sh` 建表完成后会自动探测服务器能否访问 Docker Hub：

| 探测结果 | 部署模式 | 说明 |
|---|---|---|
| **能访问 Docker Hub** | Docker Compose 全量 | `backend` + `frontend` 两个容器，正常构建镜像 |
| **无法访问（内网）** | **内网直连** | 后端用服务器自带 Java 8 直接 `java -jar app/zing-doctor.jar`；前端复用服务器已有 `nginx:stable` 镜像托管静态页。**不拉取任何外网镜像** |

内网直连模式下：
- 后端以 `ICU_DATA_PROVIDER=sql` 启动（连接真实 ICU 库），进程号写入 `backend.pid`，日志在 `logs/backend.log`
- 前端容器 `zing-doctor-frontend` 映射 `2001:80`，自动生成 nginx 反代配置（`/api`、`/entry` 转发到本机 `8081`）
- 重复部署会自动停旧进程/容器再启动

> 本手册配套交付包已内置 `app/zing-doctor.jar`（后端可执行包）与两个架构的 docker-compose 二进制，内网服务器无需联网即可完成部署。

等待构建完成后查看状态：

```bash
docker compose ps              # backend/frontend 都应为 Up
docker logs zing-doctor-backend --tail 50   # 确认 Started ZingDoctorApplication
```

## 6. ICU 系统外链对接（联调）

1. 页面编码已注册（共 14 个，完整清单见 `docs/02-外链传参规范.md` §1），常用例如：
   - `abx-patient-list` → 疑似感染患者列表（无需业务参数）
   - `abx-decision` → 单患者决策（需携带 `patientId` 或 ICU 住院号 `inHospitalNo`）
   - `abx-pkpd` → PK/PD 剂量优化（`patientId` / `inHospitalNo`）
   - `abx-ddd` / `abx-mdro` → 使用强度分析 / 细菌培养监测（`departCode`）
   - `sepsis-bundle` / `apache2-score` → 集束化治疗 / APACHE II 评分（`inHospitalNo`）
   - `apache2-overview` / `ards-monitor` / `handover-board` / `discharge-stats` → `departCode`
2. 签名：HMAC-SHA256，密钥 = 医生系统 `EXTERNAL_LINK_SECRET`，规范见 `docs/02-外链传参规范.md`。
3. 外链地址：`http://100.120.1.104:2001/entry/abx-decision?expire=..&sign=..&patientId=..`
4. ICU 侧实现：按规范自行签名，或调用医生系统 `POST /api/external/token` 签发。
5. 首次联调用 curl 直接打开外链 URL 验证，再接入 ICU 系统内跳转。

## 8. 常见问题

| 现象 | 原因与处理 |
|---|---|
| ICU 表不存在 | 模式名/表名大小写：本 SQL 用 `"zing_icu_db_prod"."patient_info"`（小写）。已确认模式存在；若具体表名大小写不同，按实库调整。验证：`SELECT TABLE_NAME FROM ALL_TABLES WHERE OWNER='ZING_ICU_DB_PROD';` |
| 列表为空（sql 模式） | ① 确认 `patient_info` 有 `is_in_depart=1` 的在科患者；② 任一筛选条件命中。验证：`SELECT COUNT(*) FROM "zing_icu_db_prod"."patient_info" WHERE is_in_depart=1;` |
| 达梦连接超时 | 确认 100.120.1.104 → 100.120.1.102:14236 网络通；后端容器内 `telnet 100.120.1.102 14236` |
| 外链 403/签名失败 | 密钥不一致或 `expire` 过期（默认 10 分钟）；确认 `EXTERNAL_LINK_SECRET` 与 ICU 侧一致 |
| 端口冲突（2001/8081） | 部署机被占用时改 docker-compose.yml 映射端口 |
| 达梦驱动缺失 | 驱动已随项目 `lib/` 打包，勿删 `lib/DmJdbcDriver18-*.jar` |
