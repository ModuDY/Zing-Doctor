# 医生交班览表与患者出科统计 · 产品设计方案

> 版本：设计稿 v1 · 2026-09-13
> 变更：2026-09-15 —— 新增「导入上一班」：医生填写本班病情变化时可一键把上一班次记录**追加**到输入框末尾（不覆盖已写内容），对应接口 `GET /api/handover/previous-note`
> 定位：把「一个班次的科室全貌」自动汇总到一张表上，替代手工誊抄交班本；同时提供患者出科统计（含出科诊断、出科转归）用于月度质控与上报。

## 一、背景与定位

### 1.1 解决什么问题

- 交班需要在几分钟内讲清「**新入、危重、异常、待办**」，人工翻病历无法在交班前完成；
- 交班内容散落在监护、检验、医嘱、护理记录多个系统，**缺乏一屏汇总**；
- 出科患者需要按时间段统计（诊断、转归、住院日），手工汇总耗时。

### 1.2 设计原则

1. **区间口径用户锁定**：默认取「最近一个已完整封板的全天班次」，保证数据完整（不会看到"还在产生"的半截数据）；
2. **一次批量取数**：每类数据一条 SQL 按科室查全，Java 侧按 `patient_id` 分组，**禁止逐患者 N+1**；
3. **手工补充与自动汇总并存**：病情变化由医生填写（一患者一班一条），其余字段自动汇总。
4. **上一班可继承、不可覆盖**：医生可一键导入上一班次记录，内容**追加**到本班输入框末尾（带 `【上一班 MM-DD】` 前缀），绝不覆盖本班已写内容；无上一班记录时给出提示而非清空。

## 二、班次（Shift）解析规则

| 规则 | 说明 |
|---|---|
| 班次定义来源 | 业务库 `config_shift`（开始/结束时分与日偏移），未配置时回退默认 **07:01 ~ 次日 07:00**（全天班） |
| 默认取样 | 从「今天」逐日回溯最多 6 天，取**第一个结束时刻 ≤ 当前时间**的班次（即最近一个已封板的全天班） |
| 举例 | now=09-07 16:46 → `[09-06 07:01, 09-07 07:00)`；now=09-08 03:00 → 仍是 `[09-06 07:01, 09-07 07:00)`（当天 07:00 未到） |
| 用户指定日期 | `shiftDate=D` 表示「D 日全天班」= 数据区间 `[D-1 07:01, D 07:00)`，作为查询结束日 |
| 区间内的两种口径 | **班内统计**（出入量 / 检验异常 / 新入出科 / 病情变化）用封板区间 `[start, end)`；**最新生命体征 / 当前器官支持**用 `[start, now]`，保证反映"当前状态" |

## 三、交班览表数据结构

### 3.1 汇总指标（`Summary`）

| 指标 | 判定 |
|---|---|
| 总患者数 | 在科患者数 |
| 机械通气 | `patient_info.ventilator_code` 非空 |
| CRRT | `patient_crrt_record` 命中（覆盖 `crrt_device_code` 判断） |
| ECMO | `ecmo_device_code` 非空 |
| 使用升压药 | 班内存在血管升压药医嘱（按患者去重药名） |
| 发热 | 班内最高体温 **≥ 38.5 ℃** |
| 检验异常 | 该患者存在至少 1 条异常检验 |
| 感染性休克 | `patient_info.is_sepsis_shock = 1` |
| 隔离 | `isolation_status` 非空且非 `0` |
| 新入科 | 入科时间落在封板区间内 |
| 已填病情变化 | 已保存交班记录的患者数 |
| 出科 | 班次内出科患者数 |

### 3.2 患者卡片（`HandoverPatientCard`）字段

**基础信息**：住院号、姓名、性别、年龄+单位、床号、入科/出科时间、诊断（`diagnosis_content`）、过敏史、主管医生、住院医生、体重、病区、科室。

**静态标记**：机械通气、CRRT、ECMO、隔离（含隔离方式）、感染性休克、ARDS、本班新入。

**动态数据**：

| 类别 | 取数规则 |
|---|---|
| 生命体征 | 最新值（SQL 按 `item_time DESC`，**有创血压优先于无创**）；按 `item_code` 优先、`item_name` 兜底归入 心率/血压/呼吸/体温/SpO₂ 等槽位 |
| 最高体温 | 班内体温记录最大值，≥38.5 置 `fever` |
| 入量 | ① 其它入量（`module_code='io_in'` 的非药品入量）累加；② 药品入量（`is_to_io=1` 的医嘱执行量，含 07:00 边界处理）累加 |
| 出量 | `config_io_item.io_type='o'` 的所有记录累加 |
| 尿量 | 固定 `item_code='ii_nl'` 累加；有导尿管显示为「xxx / C」 |
| 平衡 | 优先取记录中的「平衡」项；缺失时用 **入量 − 出量** 兜底 |
| 检验异常 | ① `alarm_flag` 非空且非 `0`/`N`/不含「正常」→ 异常；② 数值结果超出 `low_value / high_value` → 异常。计数 + 最多展示 3 条「项目 结果 单位」 |
| 在用升压药 | 班内血管升压药医嘱，按患者去重药名 |
| 在用抗菌药 | 班内抗菌药医嘱，经**白名单 + 黑名单**过滤后展示（与脓毒症模块同一套词表） |
| 手工交班 | 一患者一班一条：`condition_change`（病情变化）+ 填写人 + 时间；支持从上一班次导入（追加） |

### 3.3 单患者交班详情（抽屉懒加载）

在卡片基础上补充：生命体征明细、出入量明细（项目出入量 + 医嘱执行入量）、出入量按项目汇总、升压药明细、抗菌药明细、检验明细。

## 四、患者出科统计

### 4.1 查询口径

`IcuPatientMapper#selectDischargedPatients(startTime, endTime, departCode)`：

```sql
FROM patient_info pi
WHERE pi.del_flag = 0
  AND pi.out_depart_time IS NOT NULL
  AND pi.out_depart_time >= #{startTime} AND pi.out_depart_time < #{endTime}
  AND (#{departCode} = '' OR pi.depart_code = #{departCode})
ORDER BY pi.out_depart_time DESC
```

以**出科时间**落在区间为口径（与 DDD/MDRO 的出科口径一致，便于交叉核对）。

### 4.2 返回字段

| 列 | 来源 | 说明 |
|---|---|---|
| 患者姓名 / 床号 / 住院号 | `patient_info` | — |
| 入科诊断 | `patient_info.diagnosis_content`（`CAST AS VARCHAR(2000)`） | 长文本截断保护 |
| 入科时间 / 出科时间 / 出院时间 | `in_depart_time / out_depart_time / out_hospital_time` | — |
| **出科诊断** | `patient_info_diagnosis.diag_name` | 取**离出科时间最近的前 3 条**（按优先级用「、」拼接，同名去重；不足 3 条时有多少取多少） |
| **出科转归** | `patient_info.out_vest_type` | 字典转文字：1 转科 / 2 出院 / 3 死亡 / 4 临终 / 5 自动转院；其它值为空，页面显示 `—` |
| 主管医生 | `patient_info.charge_doctor_name` | — |

### 4.3 出科诊断取数算法（批量窗口函数，取前 3 条）

出科诊断**不写在患者主查询里**：相关子查询 + `ROWNUM` 只能取一条，取前 3 条改为「单独一条批量 SQL（窗口函数） + Java 拼串」：

`IcuPatientMapper#selectDischargedDiagnoses(startTime, endTime, departCode)`：

```sql
SELECT t.patient_id, t.diag_name FROM (
    SELECT pi.id AS patient_id, d.diag_name AS diag_name,
           ROW_NUMBER() OVER (PARTITION BY pi.id ORDER BY
             CASE WHEN d.diag_time IS NOT NULL AND d.diag_time <= pi.out_depart_time THEN 0 ELSE 1 END ASC,
             CASE WHEN d.diag_time IS NOT NULL AND d.diag_time <= pi.out_depart_time THEN d.diag_time END DESC,
             d.diag_time ASC) AS rn
    FROM patient_info pi
    INNER JOIN patient_info_diagnosis d
      ON d.patient_id = pi.id AND d.del_flag = 0 AND d.status = 1 AND d.diag_name IS NOT NULL
    WHERE pi.del_flag = 0 AND pi.out_depart_time IS NOT NULL
      AND pi.out_depart_time >= #{startTime} AND pi.out_depart_time < #{endTime}
      AND (#{departCode} = '' OR pi.depart_code = #{departCode})
) t WHERE t.rn <= 3
ORDER BY t.patient_id ASC, t.rn ASC
```

Java 侧（`HandoverServiceImpl#fillOutDiagnoses`）按 `patient_id` 分组，用「、」拼接，同名去重后写回 `out_diagnosis`。

排序语义：

1. **出科时间之前（含）的诊断优先**（`0` 排在 `1` 前）→ 避免把出科后补录的修正诊断捞进来；
2. 其中 `diag_time` 最大的 = 离出科最近（即 `rn = 1`）；
3. 若该患者所有诊断都晚于出科时间或时间为空 → 兜底按时间最早的一条开始取（保证有值）；
4. 取到 `rn ≤ 3` 为止，不足 3 条时有多少展示多少。

> 为什么不用「相关子查询套 `LISTAGG`」：需要在**相关子查询内**再做三层嵌套（排序 → `ROWNUM<=3` → 聚合），达梦对多层嵌套相关子查询的兼容性不稳；窗口函数 `ROW_NUMBER()` 在本项目其它查询已验证可用，拼串交给 Java 更可控，也顺带做了同名去重。

> ⚠️ **不使用 `ABS(diag_time - out_depart_time)`**：达梦中两个 TIMESTAMP 相减得到的是 `INTERVAL`，外层套 `ABS()` 会直接报错。若确有「严格按绝对值最近（含出科后诊断）」的需求，需改为 `ABS(CAST(...) - CAST(...))` 形式。

| 字段 | 说明 |
|---|---|

| `in_hospital_no` / `patient_id` | 住院号 / 患者 ID |

## 八、关键实现细节与风险点

| # | 问题 | 说明 / 建议 |
|---|---|---|
| 1 | 达梦时间戳相减返回 `INTERVAL` | 任何 `ABS(t1 - t2)`、`MAX(t1 - t2)` 写法都会报错，必须用 CASE 排序或 `CAST` 转换（出科诊断已按此处理） |
| 2 | `LocalTime` 不能用 `toLocalTime()` | 达梦驱动有时区偏差，代码统一用 `o.toString()` 解析（见 `parseTime`） |
| 3 | 生命体征「先到即最新」依赖 SQL 排序 | 若同项目同一秒多条，结果不确定；有创血压通过覆盖逻辑保证优先 |
| 4 | 出入量口径跨三张表（项目记录 / 医嘱执行 / config_io_item） | 任何一处 config 变更都会影响历史班次展示，配置需版本化管理 |
| 5 | 尿量固定 `ii_nl` | 若医院使用其它尿量项目编码，会漏统计 |
| 6 | 班次默认 07:01~次日 07:00 为**硬编码兜底** | `config_shift` 未配置或配置错误时，取样区间会与临床实际交班时间不一致 |
| 7 | 交班记录按 `shift_begin_time` 精确匹配 | 班次配置调整后，历史交班记录可能"对不上"新班次 |
| 10 | 「上一班」按时间倒序取，不反推班次区间 | `config_shift` 改过班次时，若按"上一个班次区间"反推会算错边界 | 刻意实现：取同住院号下 `shift_begin_time` **严格早于本班开始时间**的最近一条（`status=1`），按时间倒序取更稳 |
| 8 | 出科转归依赖 `out_vest_type` 字典值 | 出现未定义值（如 6）时显示 `—`，需与 HIS 字典对齐 |
| 9 | 出科诊断按 `patient_id` 关联 | 若 `patient_id` 为空（历史数据），出科诊断会为空，需回退 `in_hospital_no` 关联 |

## 九、后续优化建议

1. 支持**多班次（白班/夜班）**配置与切换，并在交班览表上显示相邻班次对比；
2. 交班览表增加**趋势标记**（如较上一班体温/乳酸/升压药剂量变化）；
3. 交班记录支持**模板化录入**与**一键生成交班小结文本**；
4. 出科统计增加**住院日、ICU 病死率、转归构成比**等质控指标与趋势图；
5. 出科诊断增加「主要诊断（`diag_level='01'`）优先」的取数策略。
