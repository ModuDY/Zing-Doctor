**连法**（项目根目录，工具见 `tools/dm-query/DmQuery.java`）：

```powershell
javac -encoding UTF-8 -cp "lib/DmJdbcDriver18-8.1.3.140.jar" -d tools\dm-query tools\dm-query\DmQuery.java
Get-Content my.sql -Raw -Encoding UTF8 | java -cp 'tools\dm-query;lib\DmJdbcDriver18-8.1.3.140.jar' '-Ddm.pass=口令' DmQuery
```

工具约定：多条 SQL 用 `;` 分隔逐条执行；单条最多 400 行；结果按 **TSV** 打印；SQL 文件带 BOM 会自动剔除（**踩过坑**：不剔除时第一条语句必报「无法解析的成员访问」）。

| `is_sepsis_shock` | 14 条 =1（但不在在科患者里） | 全 NULL |
| `is_ards` | 全 NULL | 1 条非空 |
| `multidrug_resistant_bacteria` | 全 NULL | 全 NULL |
| `weight` 可用数字 | 5 / 81（其余空串） | 0 / 65（其余填「卧床」） |
| `config_drug` | 3774 行，抗菌药 **127** ✅ | 14 983 行，抗菌药 **1** |
| `config_staff` / `ca_info` / `shift` | 3689 / 307 / 460 | 6577 / 337 / 288 |
| PCT 命中 | **67 / 81** ✅ | 0（近 60 天无记录） |
| 诊断命中 | 34 / 81 | 46 / 65 |
| 药敏 / 多重耐药 | 0 / 0 | 0 / 0 |
| **医生库** | **有，42 张全有数据** | **不存在 doctor 库** |

**结论**：这台达梦像「较新的生产/联调环境」——字典完整（抗菌药 127）、降钙素原有数据、医生库已建好且各模块都有真实数据。MariaDB 那台 ICU 库药品更多但抗菌药标记几乎没人维护、PCT 无数据、且**根本没有医生库**。
👉 **开发联调以这台达梦为准**；两台 ICU 库的表结构同源，但数据与字典维护程度差别很大，跨库比对别指望数字一致。

## 7. 写达梦 SQL 的注意事项

1. **小写对象名必须加双引号**：模式名是 `zing_doctor_db_prod`（小写），写成 `SELECT * FROM zing_doctor_db_prod.t` 会报表不存在；必须 `"zing_doctor_db_prod"."patient_doc_prone_record"`。系统字典里查它是**全大写**还是原样要看 `OWNER` 实际值。
2. **分页用 `ROWNUM`**：`WHERE ROWNUM <= 10`；不支持 MySQL 的 `LIMIT n`、也不支持反引号。
3. **`ALL_TABLES.NUM_ROWS` 有滞后**：例如 `quality_metric_result` 统计值 430 / 实 COUNT 557，`patient_doc_prone_cell` 统计值 237 / 实 COUNT 12。报数一律用 `COUNT(*)`。
4. **数据字典表**：`ALL_TABLES` `ALL_TAB_COLUMNS`（列名/类型/长度/精度/是否可空）`ALL_USERS` `SYSOBJECTS`。
5. **`del_flag` / `status` 在达梦侧是数值**（如 `= 0`、`= 1`），不像 MariaDB 侧的 `varchar(1)` 需要写 `= '0'` —— 两边写法不能照抄，跨库 SQL 要分别校对。
6. **`setMaxRows` 已加到工具里**，跑大表 COUNT 前先确认有没有索引；`patient_info_lis_item` 两千万行，别无脑 `SELECT *`。

## 8. 常用查询模板

```sql
-- 在科患者
SELECT "id","in_hospital_no","patient_name" FROM "zing_icu_db_prod"."patient_info"
 WHERE "is_in_depart"=1 AND "del_flag"=0 AND ROWNUM<=20;

-- 某患者的检验结果（按项目名）
SELECT "lis_item_name","lis_item_result","lis_item_unit","check_time"
  FROM "zing_icu_db_prod"."patient_info_lis_item"
 WHERE "in_hospital_no"='1000693****01' AND "del_flag"=0 AND "lis_item_name" LIKE '%降钙素原%';

-- 医生库某表字段清单
SELECT COLUMN_NAME, DATA_TYPE, DATA_LENGTH, DATA_PRECISION, DATA_SCALE, NULLABLE
  FROM ALL_TAB_COLUMNS WHERE OWNER='zing_doctor_db_prod' AND TABLE_NAME='patient_doc_prone_record'
 ORDER BY COLUMN_ID;

-- 指标定义（注意：这张表没有 rule_id / metric_name 列，主键口径是 index_code）
SELECT "index_code","index_name","unit","value_type","agg","calc_mode","impl_status"
  FROM "zing_doctor_db_prod"."quality_metric_def" WHERE "status"=1 AND ROWNUM<=20;

-- 计数规则（按指标类别查）
SELECT "count_name","numerator_code","denominator_code","percent_unit","percent_rate","target_direction"
  FROM "zing_doctor_db_prod"."quality_count_rule"
 WHERE "quality_type_code"=1 AND "status"=1 ORDER BY "sort_no";

-- 某次计算过程追溯（算错指标时从这里查）
SELECT "metric_code","fact_name","num_rows","den_rows","scanned_rows","duration_ms","sql_text","calc_time"
  FROM "zing_doctor_db_prod"."quality_calc_trace" WHERE "run_id"=14 AND ROWNUM<=20;
```

## 9. 安全提醒

- 全程只执行了 `SELECT` 和数据字典查询，**没有写任何数据**。
- `SYSDBA` 是最高权限账号：日常联调应向 DBA 申请只读账号。达梦建只读用户示例：
  ```sql
  CREATE USER ZING_RO IDENTIFIED BY "口令";
  GRANT SELECT ON "zing_icu_db_prod"."patient_info" TO ZING_RO;   -- 逐表授权
  ```
- 口令不要写进 `conf/db.conf`（该文件被 git 跟踪）；本地用 `-Ddm.pass=` 传参或临时文件，用完删除。
