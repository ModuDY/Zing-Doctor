## 2. 安全态势总评

边界模型存在**三层结构性失效**，叠加后「内网可信」假设不成立：

1. **认证可被绕过** —— JWT 未固定算法（alg=none 伪造任意账号）+ 外链签发接口免鉴权 + 静态 ICU token 永不过期。
2. **授权模型缺失** —— 全仓无角色表、无方法级鉴权；"管理员" 是 `sys_param.WORKBENCH_SUPER_USERS` 里的一份名单，而该表本身可被任何已认证主体写入 → 自我提权只需一次 POST。其上还有 40+ 业务写端点对 "通过通道鉴权" 的主体全量开放。
3. **秘密管理失效** —— 数据库 root/SYSDBA 口令、JWT 密钥、外链 token、第三方 hipToken、可复算口令散列，全部以明文形式提交在仓库与交付包中。

## 5. 待修复清单（按建议顺序）

### 5-1 `icu-static-token-no-expiry-no-replay`（High，收尾项）
现状：取值真源已统一到 `ExternalIcuTokenProvider`，但 token 仍不过期、不可吊销。
建议：在 sys_param 增加 `EXTERNAL_LINK_ICU_TOKEN_EXPIRE`（或改为双 token 滚动：当前值 + 上一值，配 `rotatedAt`），校验时超期即 401；轮换窗口内允许旧值，窗口结束旧值失效。此项可与 §5-2 一起做，避免两次改签署协议。

### 5-2 `external-signed-link-replay-unbound`（High，需前端联调）
建议：`SignatureUtil.canonical` 加入 `path` + `method`（必要时 `nonce`），校验端从请求上下文取实际值参与 HMAC；`ExternalLinkService` 与前端签发调用同步改。一次性 nonce 需缓存（Caffeine 已有依赖）记录已用值，过期清理。

### 5-3 `quality-ip-whitelist-xff-spoof`（High）
建议：取客户端 IP 时不信任 XFF 首段，改为「从右向左跳过可信代理」或直接使用 `request.getRemoteAddr()`（部署在 nginx 之后时由 nginx 覆写 `X-Real-IP` 并只信该头）；同时给 8081 直连加来源限制。

### 5-4 凭据与信息泄露组（可并行）
