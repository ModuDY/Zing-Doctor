# ARDS 俯卧位通气治疗记录 · 设计方案（评审稿）

> 版本：v4.1 · 2026-09-17 · 状态：**待评审**（评审通过后方可进入开发）
> v4 变更：① **不做告警**（无异常汇总、定位、复核、中断告警）；② 归档调用**现有归档接口**，参数在「参数设置」维护；③ **取消沿用值**，窗口内无数据一律置空转手工；④ **不做阈值配置**，参考区间内置固定，打印为真实 1:1 预览；⑤ 新增**参数设置屏**与 **APACHE II 显示开关**（一处管四处）。新增 UR-10、SR-21/SR-22、RISK-013；移除告警与阈值配置相关控制。
> v4.1 变更：待确认项收口——Q2''（残余风险）**临床评审接受，不实现任何告警或补偿代码**；Q4'（归档）**与 APACHE II、SOFA 评分共用同一接口与传参**，仅文档类型编码不同；Q5''、Q8 **不再讨论**（维持 ±15/±60 min、参考区间内置）；Q9 **默认显示 + 全院统一**；Q7 **打印不加条码/病历号、单面**。
> ⚠ RISK-002、RISK-005 残余风险（3×2=中）已由临床评审明确接受（Q2''），**系统中不实现任何告警或补偿代码**，异常发现依赖界面标红与打印件人工核对。
> 依据：纸质《ARDS 俯卧位通气治疗记录表》（58 行 × 14 列，37 项参数 × 11 个时点）
> 方法：V 模型 + INCOSE 需求工程 + ISO 14971 风险管理 + ISO 13485 设计控制
> 配套原型（附件目录 `docs/ards-prone/`）：`index.html`（目录）/ `list.html`（列表）/ `record.html`（填写 · 时点配置抽屉 · 打印预览与 HIS 回传）

本文是**工程分析与受控设计文档**，不构成医疗器械注册/认证结论。本模块是否属于医疗器械软件（SaMD）及分类，须由质量/法规负责人依据现行法规判定（待确认项 Q1）。所有示例数据均为虚构。

## 一、预期用途与系统边界（阶段 0）

### 1.1 临床问题

| # | 问题 | 现有证据/现象 |
|---|---|---|
| 1 | 纸质记录分散、易缺项 | 37 项 × 11 时点 = 407 个单元格，跨 12–16 小时、跨班次填写，漏填与事后补录失真难以发现 |
| 2 | 疗效无法量化 | 「这次俯卧位有没有效」依赖翻纸质单逐列比对，无法给出 P/F 变化、ΔP 趋势 |
| 3 | 并发症与终止原因非结构化 | 勾选框 + 自由文本，无法统计发生率、无法回溯 |
| 4 | 数据重复抄写 | 呼吸机参数、生命体征、血气已在监护仪/LIS 中存在，仍由护士手工转录，转录错误无痕 |

### 1.2 预期用途（草案）

供 ICU 医师与护士在**中重度 ARDS 患者俯卧位通气治疗期间**，按预定监测时点**记录、查看、打印**患者生命体征、呼吸机参数、血气/氧合、镇静镇痛与安全评估数据，并记录并发症与终止指征；用于床旁监护记录、交接班与病历归档。

**使用者画像**：ICU 护士（主要录入，床旁/平板/夜班）、ICU 医师（审核、终止决策、签名）、护士长/质控（统计与回溯）、信息科（接口运维）。

**使用环境**：床旁（站立操作、戴手套）、护士站（桌面）、夜班（低照度、低年资单独值班）、网络与设备可能中断。

### 1.3 系统边界

**包含**：记录创建/编辑/提交/打印/复制新建、时点模板管理、自动采集值回填、检验值同步、计算项、内置参考区间标红、并发症与终止指征结构化、签名与审计留痕、列表与统计。

**不包含（显式排除）**：
- 不下发任何参数到呼吸机/输液泵，**不构成闭环控制**；
- 不做 ARDS 诊断、不给出治疗建议（氧合改善评价仅作展示，由医师判断）；
- 不替代病历系统与护理记录系统，打印件作为归档载体交由现有流程管理；
- 不实现报警推送到移动设备（当前仅页面内提示）；
- 不处理跨院区主数据同步（依赖 EMPI/住院号，接口侧强校验）。

### 1.4 外部实体与初始接口

| 外部实体 | 方向 | 内容 | 初始接口（待 ICD 化） |
|---|---|---|---|
| 监护仪/呼吸机数据中心 | 入 | Vt、PEEP、FiO₂、RR、Ppeak、Pplat、HR、BP、MAP、RR、T、SpO₂ | `patient_observe_module_item_record` + `config_observe_item`（按 `item_code`/`item_name` 匹配） |
| LIS（检验） | 入 | pH、PaO₂、PaCO₂、HCO₃⁻、BE、Lac | `patient_info_lis_item`（按项目名称匹配） |
| HIS / 患者主索引 | 入 | 姓名、性别、年龄、住院号、床号、诊断、入院日期 | `patient_info` / `patient_info_diagnosis` |
| HIS / 病历归档（ICD-04） | **出（已确认需回传）** | 打印 PDF、记录编号、文档号、签名信息、打印人/时间 | **调用系统现有归档接口**（ICD-04）：与 **APACHE II、SOFA 评分归档为同一个接口，传参结构完全一致**，仅文档类型编码不同（ARDS_PRONE_REC / APACHE2 / SOFA）；接口选择、文档类型编码、模板编号、科室编码、超时、重试、启用开关在「参数设置」中维护，**不新开发接口**；失败可重传，同一记录幂等 |
| 本系统既有模块 | 双向 | ARDS 监测（分级、氧合指数）、交班览表 | 内部服务调用 |

## 二、临床工作流与异常分支

### 2.1 主流程

选择患者 → 新建记录（自动带入基本信息）→ 设定俯卧位开始 → 逐时点录入（自动值回填 + 手工项补录）→ 结束俯卧位 → 并发症/终止指征 → 双人签名提交 → 打印归档。

### 2.2 必须覆盖的异常分支（设计已考虑，实现需逐项验证）

| 分支 | 设计应对 |
|---|---|
| 抢救/紧急复仰 | 允许跳时点直接结束；结束时间必填，未填时记录停留在「进行中」并在列表页提示 |
| 断网 / 接口中断 | 离线缓存本地暂存，恢复后自动同步；页面顶部常显数据源健康状态（已采集/滞后/心跳中断） |
| 采集窗口内无数据 | 生命体征/呼吸机（±15 min）与血气/检验（±60 min）窗口内取不到数据时，一律**置空标「未采集」，转手工录入**；**不沿用历史值、不自动推算、不做陈旧判定** |
| 数据源中断 | 顶部仅展示数据源「最近更新时间」供人工判断，**不做中断告警与提醒** |
| 转科/转床/换床位 | 采集以 `patient_id` 强绑定；住院号变更时提示人工复核身份，禁止自动跟随床位切换 |
| 身份不明/急诊无名氏 | 不允许自动采集回填，全部手工录入并标记「身份待核对」 |
| 交接班 | 列表页显示「最后更新人/时间」与已填进度；交班时未提交记录进入交接提醒 |
| 误填到错误时点 | 时点锁定：非当前时点编辑需填写原因；修改留原值与新值 |
| 误用：代签/共用账号 | 实名账号签名，护士+医师双人，签名不可代填 |
| 补录/事后修改 | 提交后**不设修改时限**，任何更正均保留原值、新值、修改人、时间、原因并写入审计日志 |
| 打印件回传 HIS 失败 | 列表页标记「失败 · 待重试」，支持手动重传；同一记录重复回传不产生重复文档（幂等） |

## 三、数据接口映射（ICD 摘要）

| 数据域 | 数据元 | 来源表/项 | 单位 | 时点窗口 | 时效要求 | 失效处理 |
|---|---|---|---|---|---|---|
| 呼吸机参数 | 潮气量 Vt | `patient_observe_module_item_record` `oi_呼末潮气量` | ml/kg（按理想体重换算） | 计划时间 ±15 min | ≤5 min 可见 | 置空标「未采集」，转手工（需填原因） |
| 呼吸机参数 | PEEP / FiO₂ / 设定RR / Ppeak / Pplat | `oi_peep`、`oi_FiO2(设置值)`、`oi_呼吸频率(设置值)`、峰压/平台压项（待确认 Q3） | cmH₂O / % / 次/min | 同上 | 同上 | 同上 |
| 生命体征 | HR / RR / SpO₂ / T | `oi_hr`、`oi_hxpl`、`oi_spo2`、体温项 | 次/min、%、℃ | 同上 | 同上 | 同上 |
| 生命体征 | SBP / DBP / MAP | 有创收缩压/舒张压优先，无创兜底；MAP 取采集值，无则 (SBP+2×DBP)/3 并标注「推算」 | mmHg | 同上 | 同上 | 同上 |
| 血气 | pH / PaO₂ / PaCO₂ / HCO₃⁻ / BE | `patient_info_lis_item`：`PH值`、`氧分压`、`二氧化碳分压`（HCO₃⁻/BE 项目名待确认 Q3） | — / mmHg / mmol/L | 计划时间 ±60 min（血气非连续） | ≤15 min 可见 | **置空标「未采集」，转手工录入（不沿用历史值）** |
| 血气 | Lac | 同上：`乳酸` | mmol/L | 同上 | 同上 | 同上 |
| 计算 | P/F、ΔP、P/F 变化、持续时长 | 系统计算 | mmHg / cmH₂O / h | — | 实时 | 缺任一项显示「待补」，**不得显示 0** |
| 手工（缺失数据元） | Ppeak、Pplat、HCO₃⁻、BE 等观察项/检验中无对应数据元的参数 | 人工 | — | — | — | 一律标记来源「手工」，界面角标与自动值区分（SR-20） |
| 手工 | 镇静镇痛、安全评估、并发症、终止指征、备注、签名 | 人工 | — | — | — | — |

**取值与失效规则（本轮已确认）**

| 判定 | 连续类（生命体征 / 呼吸机） | 检验类（血气 / 检验） |
|---|---|---|
| 窗口 | 计划时间 ±15 min | 计划时间 ±60 min |
| 窗口内有值 | 取窗口内最近一条 →「已采集」 | 同 |
| 窗口内无值 | **置空**标「未采集」，转手工录入（不沿用历史值、不推算） | 同 |
| 数据源中断 | 展示「最近更新时间」供人工判断，不告警 | 同 |

通用要求：所有值携带 `来源系统 + 采集时间 + 原始值`；接口侧逐项登记失效模式（丢失/重复/乱序/超时/错配）并纳入风险表。

## 四、危害分析与风险控制（ISO 14971 摘要）

分级定义：**S1 轻微 / S2 中度 / S3 严重 / S4 死亡或永久伤害**；**P1 极少 / P2 偶发 / P3 可能 / P4 频繁**。可接受准则：S4 任一 P 均不可接受；S3 + P≥3 需两项独立控制并有验证证据；分析后不得为「过关」修改准则。

| ID | 危害源 → 危害情况 → 伤害 | S | P | 控制措施（按优先级） | 转需求 |
|---|---|---|---|---|---|
| H01 | 患者错配（转床/住院号变更）→ 数据记到他人名下 → 依错误数据治疗 | 3 | 2 | ①身份三要素核对（床号+住院号+姓名）后解锁录入；②接口以 `patient_id` 强绑定，跨患者写入硬阻断；③切换患者时清空未保存缓存 | SR-01, SR-02 |
| H02 | 接口中断/设备掉线 → 旧值冒充实时值 → 误判氧合改善 | 3 | 3 | ①每值带采集时间戳与窗口；②窗口内无数据一律置空转手工，不沿用历史值；③顶部展示数据源最近更新时间供人工判断；④离线降级流程（**本版不做中断告警，残余 3×2=中，需临床评审接受**） | SR-03, SR-04 |
| H03 | 时点错填/漂移 → 趋势失真 → 误判疗效 | 2 | 3 | ①时点锁定，非当前时点编辑需原因；②自动值按采集时间归位；③修改留原值 | SR-05, SR-06 |
| H04 | FiO₂ 单位混用（% vs 小数）→ P/F 差 100 倍 → 错误分级与决策 | 3 | 2 | ①单位强约束（仅 %，21–100 边界校验）；②计算项只读；③异常值提示 | SR-07, SR-08 |
| H05 | 407 格中异常被淹没 → 遗漏恶化 | 3 | 3 | ①按内置固定参考区间标红；②打印件保留红字便于人工核对（**本版不做异常汇总/定位/复核确认等告警手段，残余 3×2=中，需临床评审接受**） | SR-09 |
| H06 | 自动值被无痕修改 → 数据不可信、无证据 | 2 | 3 | ①采集值只读；②修正双轨（原值+修正值+原因+人+时间）；③审计日志 | SR-06, SR-10 |
| H07 | 断网/宕机无法记录 → 记录缺失、事后补录失真 | 2 | 3 | ①离线缓存 + 恢复自动同步 + 冲突提示；②纸质降级（打印版式即降级载体） | SR-11 |
| H08 | 代签/共用账号 → 责任不清 | 2 | 3 | ①实名账号；②护士+医师双人签名；③签名记录账号/时间/终端 | SR-12 |
| H09 | 时点删除致数据丢失 → 历史不可追溯 | 2 | 2 | ①软删除 + 二次确认 + 原因；②统计与打印仍含历史 | SR-13 |
| H10 | 打印漏项/与屏幕不一致 → 归档记录不完整 | 2 | 2 | ①打印模板与页面同一数据源；②打印前必填项校验；③页脚记录编号与打印人 | SR-14 |
| H12 | 打印/归档后回传失败或重复回传 → 纸质已归档但电子病历无记录或重复 → 病历不完整、记录不一致 | 2 | 2 | ①**调用参数设置中配置的现有归档接口**；②回传记录文档号与状态，失败可手动重传；③同一记录幂等（重复回传不产生重复文档）；④列表页可见回传状态；⑤回传失败不阻断打印，但记录进入待重传队列 | SR-19, SR-22 |
| H11 | 阈值配置错误（单位/量级）→ 误报或漏报 | 2 | 2 | **功能范围移除**：不提供阈值配置能力；参考区间内置固定并随需求版本受控，调整须走需求变更与版本发布 | SR-15 |
| H13 | APACHE II 显示开关误关或只关部分位置 → 页面与文书输出不一致、文书缺项 | 2 | 2 | ①一处开关管四处（填写页/预览/打印/回传）保持一致；②默认显示；③关闭后整行重排不留空位；④打印预览所见即所得可核对；⑤开关变更留痕 | SR-21 |

> 注：控制措施优先级为「本质安全设计 → 防护措施 → 安全信息」。本设计未将「培训/提示」作为任何 S3 危害的唯一手段。
> 编号对应：上表 H01…H13 = 受控登记表 `docs/ards-prone/risk-management-table.csv` 中的 RISK-001…RISK-013（H12→RISK-012、H13→RISK-013）。

## 五、需求（UR → SR）

### 5.1 用户需求 UR（临床语言）

| ID | 需求 |
|---|---|
| UR-01 | 一次俯卧位疗程形成一条记录，可查看、编辑、打印、复制新建 |
| UR-02 | 呼吸机参数与生命体征自动带出，血气/检验自动同步，我不重复抄写 |
| UR-03 | 默认 11 个监测时点，允许按情况增删，删掉的不丢历史 |
| UR-04 | 氧合指数、驱动压、持续时长自动算，我不能也无需手改 |
| UR-05 | 异常值一眼可见，并能一键跳到异常处、标记已复核 |
| UR-06 | 断网时也能录入，恢复后自动同步且提醒冲突 |
| UR-07 | 提交需双人签名；事后修改留痕，看得出谁改了什么 |
| UR-08 | 打印还原纸质原表，可直接归档 |
| UR-09 | 列表页能看出这次俯卧位有没有效、有没有并发症 |
| UR-10 | APACHE II 评分是否出现在页面与文书里，由科室在参数设置中用开关控制 |

### 5.2 系统需求 SR（可验证）

| ID | 需求（含量化指标） | 来源 |
|---|---|---|
| SR-01 | 录入前须通过身份三要素核对（床号+住院号+姓名），任一项不匹配时禁止进入录入态 | UR-01, H01 |
| SR-02 | 所有采集数据以 `patient_id` 绑定；接口返回的患者标识与当前记录不一致时拒绝写入并记录日志 | H01 |
| SR-03 | 每个数值必须携带采集时间戳与采集窗口；生命体征/呼吸机窗口 ±15 min、血气/检验 ±60 min；窗口内取最近一条，**窗口内无数据一律置空标「未采集」并转手工录入，不沿用历史值、不做陈旧判定** | UR-02, H02 |
| SR-04 | 页面顶部展示数据源最近更新时间（监护仪/LIS），**仅作信息展示，不做告警与中断提醒** | H02 |
| SR-05 | 任何时点（含已提交记录）均允许更正且**不设修改时限**；更正须填写原因，系统保存原值、新值、修改人、时间 | UR-03, H03, H06 |
| SR-06 | 任何数据变更写入审计日志：记录 ID、时点、参数项、原值、新值、修改人、时间、原因 | UR-07, H03, H06 |
| SR-07 | FiO₂ 仅接受百分比（21–100），拒绝小数与越界值并提示；单位随值存储并在界面显示 | H04 |
