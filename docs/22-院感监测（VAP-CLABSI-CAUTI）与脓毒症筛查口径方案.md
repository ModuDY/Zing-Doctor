# 方案 22：院感线索核查、设备日与脓毒症筛查

> **版本：v2.0（数据可行性优先版）**
> **更新日期：2026-10-13**
> **状态：开发前方案 / 待院感科、ICU、信息科会签**
> **项目：zing-doctor 重症医生决策与质控平台**

## 0. 本次重设计结论

原方案将“VAP / CLABSI / CAUTI 自动监测、脓毒症筛查、质控回写”放在同一个实现闭环中，超出了当前数据库可可靠支撑的范围。本版调整为：**先做患者级证据核查，再做人审事件闭环，最后才接质控统计。**

### 当前可以承诺

1. 展示可识别的管路原始记录、起止时间和数据质量问题；
2. 汇总发热、白细胞、乳酸、诊断、抗菌药执行、培养文本等证据；
3. 生成“需要医生核查”的院感线索，不自动下 VAP、CLABSI、CAUTI 诊断；
4. 复用现有 SOFA 评分和脓毒症集束化快照形成风险线索，不把 `patient_info.is_sepsis_shock` 当权威诊断；
5. 区分查无数据、部分数据、未送检、阴性结果和查询失败。

### 当前不能承诺

- 不能仅凭 `tube_code` 记录数计算患者数、episode 数、导管日、通气日或感染发生率；
- 不能将临床 VAP 与 CDC/NHSN VAE、VAC、IVAC、PVAP 混称；
- 不能从现有培养文本可靠完成菌种、菌量、真菌排除条件和完整药敏 S/I/R 判定；
- 不能把 `ventilator_code` 等当前状态字段当历史机械通气日；
- 不能把疑似线索自动写进 `patient_tube.is_infect` 或质控分子；
- 设备日、事件审核和质控口径未会签前，不输出正式院感发生率。

## 1. 当前项目的数据可行性

下列“已存在”指代码或仓库中的数据盘点确认，不表示每个患者、每个时间窗均有完整值。历史行数是特定盘点时点的记录数，不可当作当前患者数或发生数。

### 1.1 已有数据源及可用边界

| 数据源 | 当前情况 | 本方案可用方式 / 限制 |
|---|---|---|
| ICU `patient_info` | 患者、住院、科室、转归和当前支持状态；体重字段为字符串，部分标记覆盖不足 | 用作患者主键、住院段和科室范围；`is_sepsis_shock` 不能作为唯一筛查字段 |
| ICU `patient_info_diagnosis` | 有 `diag_name`、`diag_code`、`diag_time` 等 | 用于感染部位线索和时间线，不替代人工归因 |
| ICU `patient_info_lis_item` | 千万级大表；检验和微生物信息可按住院号/时间查；培养明细以文本为主 | 仅做患者级、带时间范围查询；禁止全院无界扫描或将文本解析视为权威结论 |
| ICU `patient_info_lis` | 有报告头，当前代码按报告名关键词识别培养 | 展示报告名、标本/送检/报告时间（字段有值时）；不能自动当作阴性/阳性确证 |
| ICU `patient_observe_module_item_record` | 有体温等监测记录，需按配置表核实项目编码、单位和状态 | 展示原始观察值和趋势；记录缺失不等于临床正常 |
| ICU `patient_advice_execute` 及明细 | 有医嘱执行信息 | 以已执行时间作为用药证据；药品识别需走项目词库，不能依赖单一药品标记 |
| 医生库 SOFA 评分记录 | 当前系统有 SOFA 评分功能及记录 | 复用原评分、时间和分项；计算变化须有可信基线和同一比较口径 |
| 医生库脓毒症集束化记录 | 当前有 `patient_doc_sepsis_bundle_record` 和集束化页面 | 只读已有记录/快照，不另造一套 bundle 计算 |

### 1.2 管路数据的表名和语义尚未闭环

现有 `IcuPatientMapper` 实际查询 ICU 库 `patient_tube`，已使用字段有：

- `patient_id`、`tube_code`；
- `tube_set_start_time`、`tube_set_end_time`、`tube_take_away_time`；
- 现有 SQL 另使用 `take_time`，但它和实际拔除时间的关系未会签。

仓库的数据盘点又记录 `patient_tube_record` / `patient_tube_record_item`。当前不能把 `patient_tube` 和这两张表视为同一实体，也不能只凭项目代码推断物理表的完整字段、状态、软删除和记录粒度。

现有管路 SQL 主要用于“班次内是否存在导尿管”，尚未解决：

- 管路类型字典及多个 `tube_code` 变体映射；
- 一行记录是否代表一个完整置入—拔除 episode；
- 起止字段的权威语义、优先级及补录/撤销规则；
- 软删除/有效状态过滤；
- 同一患者同一日多条同类管路的去重；
- 气管插管记录是否等于有创机械通气记录。

因此，已有统计如“CVC 1142、PICC 102、导尿管 3003、插管约 997”只能作为**历史原始记录数**。原统计的时间范围、过滤条件和去重口径未在本方案中完整留存，不能据此宣传患者数、设备日或感染数。

### 1.3 当前关键缺口

| 能力 | 当前状态 | 影响 |
|---|---|---|
| 培养结果结构化 | 培养信息主要来自 LIS 文本/明细，标本、菌种、菌量、污染/阴性状态等映射未完整核验 | 仅展示原文和送检时间，不自动完成协议判定 |
| 药敏/耐药结构化 | 仓库盘点记录 `patient_info_lis_ast`、`patient_info_lis_ast_item`、多重耐药表为空 | 不承诺完整药敏 S/I/R 或 MDRO 识别 |
| 每日最低 PEEP / FiO₂ | 尚无经确认的稳定结构化来源和项目编码 | 暂不能自动做 NHSN VAC/IVAC/PVAP |
| 脓性痰、寒战、肋脊角痛等 | 未发现可依赖的结构化来源 | 不作为自动判定条件 |
| 真实机械通气日 | `ventilator_code` 是当前状态字段，管路与通气事件映射未验证 | 不直接作为 VAE/VAP 分母 |
| CVC 分类 | `tube_code` 多种变体，PICC/透析导管是否纳入未确认 | 不直接计算 CLABSI 分母 |
| 脓毒性休克标记 | 当前盘点显示 `is_sepsis_shock` 覆盖不足 | 不作为唯一筛查/确诊字段 |

## 2. 医学口径边界

### 2.1 临床 VAP 与 NHSN VAE 必须分开

- **临床 VAP**：按医院感染诊断标准及本院临床/院感流程，由医生或院感科确认；
- **NHSN VAE**：VAC → IVAC → PVAP 监测协议，需要连续的通气状态、每日最低 PEEP/FiO₂、体温、白细胞、抗菌药使用及呼吸道分泌物/培养等证据。

当前 PEEP/FiO₂ 来源未核实。页面只能称“呼吸机相关感染线索/通气状态核查”，不能称为已实现 VAE 或自动 VAP 监测。

### 2.2 CLABSI 与 CRBSI 不可自动等同

CLABSI 是以中心血管导管暴露和血流感染监测定义为基础的监测口径；CRBSI 是临床诊断，需更具体的临床/微生物学证据。质控配置中的 `quality_26` 名称为 CRBSI，不能把 CLABSI 线索直接填入该指标。两者的本院报表关系须由院感科确认，数据模型分别保留事件类型。

### 2.3 CAUTI 培养口径修正

原文“尿培养至少两种菌”不正确，不得保留。按 NHSN UTI/CAUTI 现行协议，尿培养通常要求达到规定菌量、**不超过两种微生物且至少一种为细菌**，并需符合相应症状、导管暴露和时间窗口径；无症状菌尿不能直接作为 CAUTI。真菌不能按细菌 CAUTI 病原体条件直接计入。正式上线前须将协议年份/版本与医院采用口径会签并锁定。

当前培养结果尚未结构化出标本、菌量、菌种和症状，因此一期只展示原始结果及缺失条件，不自动判定 CAUTI。

### 2.4 Sepsis-3 和 qSOFA 的边界

- 脓毒症风险需同时看感染证据和器官功能变化；Sepsis-3 的“感染 + SOFA 急性增加 ≥2”不能用“最新 SOFA 总分 ≥2”替代，必须定义基线及比较时间窗；
- qSOFA 只能作为风险提示，不能作为唯一筛查入口或诊断依据；
- 脓毒性休克涉及血管活性药、MAP、乳酸及复苏背景，不能由 `is_sepsis_shock` 或单次乳酸值自动确诊；
- 现有集束化记录是治疗过程数据，不等同于脓毒症确诊事件。

## 3. 一期产品：患者级院感线索核查

### 3.1 定位与提示

一期不是“自动院感诊断页”，而是患者级**院感线索核查页**，可从患者工作台或诊疗摘要进入。页面固定提示：

> 本页面展示可查询的数据库证据和规则线索，仅供医生/院感科核查，不等同于院感诊断或质控确诊结果。

### 3.2 页面区块

#### A. 管路/设备事实

展示设备原始名称和 `tube_code`、起止时间原文、当前推断状态（在位/已结束/时间不完整/无法判断）、来源表及同步时间。**“记录存在”与“已计入设备日”分开显示。** 未会签的设备日不显示为确定数值。

#### B. 感染证据时间线

按时间排序展示：体温、WBC、乳酸等检验/观察；培养送检与报告原文；抗菌药实际执行时间与药品原名；感染相关诊断；SOFA 与集束化记录。每条证据保留时间、原值、单位、来源和解析状态；解析失败的原文不能静默丢弃。

#### C. 线索卡片

| 线索 | 候选证据 | 展示文案 |
|---|---|---|
| 导管相关血流感染 | 中心导管候选记录 + 血培养、体温、血压/升压药等证据 | “存在 CLABSI/CRBSI 核查线索；需核对导管关系并评估其他感染来源” |
| 导尿管相关尿路感染 | 导尿管候选区间 + 尿培养/体温/抗菌药证据 | “存在 CAUTI 核查线索；培养条件和症状资料待核” |
| 呼吸机相关感染 | 通气相关证据 + 呼吸道培养、体温/WBC、抗菌药等 | “存在呼吸机相关感染线索；VAE 分层数据未完备” |
| 脓毒症风险 | 感染证据 + 可比较的 SOFA 变化，或 qSOFA 风险项 | “存在脓毒症风险线索，不替代临床诊断” |

每个线索必须能展开看到触发证据、时间窗、缺失条件和规则版本。当前的 `发热 + 新用抗菌药 + 带管` 只可用于人工核查队列候选，不是院感事件诊断标准。

#### D. 人工核查

若院方批准医生系统保存审核结果，可选择：待核查、临床确认、已排除、资料不足、撤销。审核必须填写依据/原因，保存操作人、时间和版本。**人工确认只表示系统记录了审核意见，不意味着系统自动诊断。** 若未获准，本期保持只读，不开发写入。

## 4. 设备日：先会签再计算

### 4.1 计算原则

设备日不是管路记录数，也不是患者数。计算前需完成设备字典、实际置入/拔除字段、有效状态、患者住院/ICU episode 和重复记录口径确认。

建议算法原则（需会签后固化）：

1. 同患者、同一住院/ICU episode、同设备类别、同自然日按患者设备日去重；
2. 某自然日只要在任意时段处于设备在位区间，计 1 个患者设备日；同日置入/拔除也按当日在位处理；
3. 同日同类多根管路不直接累加为多患者日，除非报表明确统计“管路日”；
4. 空起始时间、逆序时间或结束字段冲突时标为 `UNKNOWN`，不得默认为持续在位或零日；
5. 同日拔除后再置入、跨月、跨科、出入 ICU、删除/补录的处理规则必须写测试并由院感科确认。

### 4.2 版本化管路分类字典

建议在医生库维护字典，不在 SQL 中散落硬编码：

| 字段 | 用途 |
|---|---|
| `tube_code` | ICU 源系统原始编码 |
| `device_category` | `CENTRAL_LINE` / `URINARY_CATHETER` / `INVASIVE_VENTILATION` / `OTHER` |
| `include_denominator` | 是否纳入对应设备日 |
| `effective_from/to` | 字典版本生效范围 |
| `confirmed_by/time` | 会签人员与时间 |
| `remark` | PICC、透析导管、气切、无创通气等说明 |

未纳入已确认字典的编码显示“待分类”，不计入分母。

### 4.3 VAE 的前置条件

只有验证以下源数据连续、结构化且可追溯后，才开发 VAC/IVAC/PVAP：有创通气状态/起止、每日最低 FiO₂ 与 PEEP、稳定/恶化期天数、体温/WBC、抗菌药开始及持续、脓性分泌物/下呼吸道培养。此前 `quality_24/25` 保持待接或待定，不以 `ventilator_code` 代替。

## 5. 三类线索具体范围

### 5.1 CLABSI / CRBSI

正式监测需要中心导管暴露、事件日期关系、符合协议的血流感染实验室证据，以及排除其他感染来源等条件。当前中心导管类别和血培养结构化判定未完成。一期只展示候选管路、血培养原文、体温/血压/升压药和其他感染部位证据；不写 `patient_tube.is_infect`，不更新 `quality_26`。

### 5.2 CAUTI

现有代码使用 `tube_code='tube_导尿管'` 判断班次内是否有导尿管，可作为候选数据源，不代表正式设备日已经核实。页面展示导尿管原始区间、尿培养原文、体温、可用症状、抗菌药执行和其他感染来源。缺少症状/菌量/标本等关键条件时，状态为“资料不足/待核查”，不能显示为“CAUTI 阴性”。`quality_425/426` 暂不出正式值。

### 5.3 VAP / VAE

气管插管记录、当前 `ventilator_code` 非空或呼吸机医嘱，只能表明存在通气相关证据，不足以证明有创通气日或 VAP/VAE。一期展示可查到的气道/通气记录、呼吸道培养原文、体温/WBC、抗菌药执行及 PEEP/FiO₂ 数据可得性；缺 PEEP/FiO₂ 时明确显示“无法进行 VAC 分层”，不填默认值。

## 6. 脓毒症风险筛查

### 6.1 复用现有功能

现有脓毒症集束化页面和 `patient_doc_sepsis_bundle_record` 继续负责治疗过程/快照。本方案只聚合筛查证据，不重做 1h/3h/6h bundle。

### 6.2 候选流程

1. 汇总感染相关诊断、培养送检/报告、体温、WBC、乳酸、抗菌药执行等感染证据；
2. 获取 SOFA 评分时间序列，展示具体两次评分、基线、分项和数据完整性；
3. 仅在基线与比较时间窗明确时计算 `ΔSOFA`；缺失分项返回 `PARTIAL/UNKNOWN`，不补默认分；
4. qSOFA 作为辅助风险信号，不作为唯一筛查/诊断；
5. 由医生确认临床结论；确认记录与质控统计解耦，待会签后接入。

输出分为“原始事实 / 风险线索 / 待临床确认 / 质控事件”四层，避免把某个风险标志或 bundle 完成情况当成诊断。

## 7. 数据状态与审核状态

### 7.1 数据状态

| 状态 | 含义 |
|---|---|
| `FOUND` | 查询成功并找到可展示的原始数据 |
| `PARTIAL` | 有数据但缺少必要字段，如有培养结果但无菌量/标本映射 |
| `NOT_RECORDED` | 查询成功但时间窗内无记录 |
| `NOT_APPLICABLE` | 当前情境不适用 |
| `UNKNOWN` | 查询失败、时间冲突或无法解释 |

### 7.2 临床审核状态

`PENDING`、`CONFIRMED`、`EXCLUDED`、`INSUFFICIENT`、`REVOKED`。审核状态不覆盖数据状态；状态改变需留存人员、时间、原因和版本。

## 8. 人工审核事件模型建议

若院方同意由医生系统保存院感审核意见，建议新增医生库独立事件表，例如 `patient_infection_review_event`，不修改 ICU 源表，也不把 `patient_tube.is_infect` 当审核结果。

建议字段：

| 字段 | 说明 |
|---|---|
| `id` | 事件主键 |
| `patient_id` / `in_hospital_no` / `depart_code` | 患者及当时科室快照 |
| `event_type` | `CLABSI`、`CRBSI`、`CAUTI`、`VAP`、`VAE`、`SEPSIS`、`SEPTIC_SHOCK` |
| `event_time` | 临床事件时间，不等于审核时间 |
| `source_episode_id` | 关联管路/住院 episode；无法确定时说明原因 |
| `screen_status` / `review_status` | 线索和人工审核状态 |
| `evidence_snapshot` | 原始证据快照、查询时间及算法版本 |
| `review_reason` | 确认/排除/资料不足的理由 |
| `reviewer_id/name/time` | 审核人和审核时间 |
| `version` / `previous_id` | 版本链，禁止覆盖历史结论 |
| `del_flag` | 仅用于撤销流程，不物理删除审计历史 |

未得到院方授权前只做只读，不创建审核写接口。

## 9. 质控指标接入策略

仓库中的 `07_device.yaml` 将相关指标标为 `PENDING_SOURCE` 或 `PLACEHOLDER`，`fact_device` 亦未启用；因此它们不是当前已可计算的指标。

| 指标 | 当前配置/缺口 | 本版处理 |
|---|---|---|
| `quality_17/18/19` | 管路事件、计划属性、48h 配对未核 | 保持待接，不以记录数代替事件数 |
| `quality_24` | VAP/VAE 定义及临床确认未定 | 保持占位，不由培养文本计数 |
| `quality_25` | 有创通气日源和切分规则未定 | 保持占位，不用当前 `ventilator_code` 代替 |
| `quality_26` | 指标名为 CRBSI，源映射及 CLABSI 关系待确认 | 保持待接，不从线索回写 |
| `quality_27` | 中心血管导管日的分类/去重待定 | 保持占位 |
| `quality_425` | CAUTI 事件条件不具备结构化支持 | 保持占位 |
| `quality_426` | 导尿管区间和设备日规则未会签 | 保持占位 |

正式接入必须满足：事件分子来自独立审核记录；分母可追溯到患者与自然日；算法、周期、科室、事件口径留版本；错误/缺数据不能当 0；质控结果可下钻至原始证据。

会签后的候选公式：

```text
CLABSI/CRBSI 率 = 确认事件数 ÷ 中心血管导管日 × 1000
CAUTI 率       = 确认事件数 ÷ 导尿管日 × 1000
VAP 率         = 确认的临床 VAP 事件数 ÷ 有创机械通气日 × 1000
```

公式不代表当前数据已经具备；指标名、事件类型、去重、分母和周期由院感科/质控部门签字后固化。

## 10. 分期计划

### 阶段 0：源数据与口径会签（前置）

- 核对 `patient_tube`、`patient_tube_record`、`patient_tube_record_item` 表结构和样例，明确关系；
- 确认管路类型、起止字段、软删除/撤销/补录语义及 episode；
- 核实培养项目编码、标本、阴性/阳性/污染/未报告等取值；
- 盘点 PEEP、FiO₂、通气状态、呼吸道分泌物实际数据源与频率；
- 确认临床 VAP、NHSN VAE、CLABSI、CRBSI 及质控报表关系；
- ICU、院感科、信息科会签。

### 阶段 1：只读患者级线索核查

管路原始数据与质量、感染证据时间线、三类院感线索、脓毒症风险线索、状态区分、科室权限和查询失败降级。**不接正式质控分子分母，不新增确诊写入。**

### 阶段 2：人工审核闭环

在获准后增加独立事件记录、待核/确认/排除/资料不足/撤销、审核理由、证据快照、版本链和权限控制。

### 阶段 3：设备日与质控指标

阶段 0 会签、阶段 1 回溯验证、阶段 2 审核闭环通过后，再开发设备日及 `quality_26/425/426` 等确定口径指标；重新评估 `quality_24/25` 是否具备源数据。

### 阶段 4：VAE 与脓毒症增强

PEEP/FiO₂ 连续数据验证后再做 VAC/IVAC/PVAP；SOFA 基线、急性变化、感染窗口及休克证据会签后再增强筛查。短信/院内通讯另行立项。

## 11. 工程与医疗安全约束

### 查询性能

- ICU 大表查询必须有患者键/住院号、科室授权范围和时间窗；
- 禁止按培养关键词、`doc_code` 或 `tube_code` 做无界全院扫描；
- 列表按患者集合批量取数并在服务端分组，禁止患者循环 N+1；
- 设备日和全科统计优先批处理/缓存，页面不逐患者实时扫大表；
- 记录源表、时间窗、数据状态和查询耗时。

### 权限与外链

- 患者接口必须校验患者所属科室和当前用户范围；
- 外链免登录继续受来源系统科室范围约束，不因 URL 的 `patientId` 绕过授权；
- 审核、撤销、历史查看分别授权；
- 证据快照不得越权包含其他患者信息。

### 临床安全

- 保存原始值、单位、时间、来源和解析结果；
- 未查询、无记录、阴性和查询失败分别呈现；
- 字典、阈值、算法及数据源版本可追溯；
- 自动提示上线前用历史病例回顾性验证误报/漏报，并由临床确认阈值；
- 不自动诊断、不自动开立或调整医嘱、不替代院感科判断。

## 12. 验收标准

### 数据正确性

- 每条线索可展开到原始证据、时间窗和解析状态；
- 同一患者同类设备同一自然日不因多条记录重复计患者设备日；
- 起止缺失/逆序、同日置入拔除、跨月/跨科/跨 ICU episode 均有测试；
- 培养未送检、待报告、阴性、阳性、解析不全和查询失败分别呈现；
- `is_sepsis_shock` 缺失不得变成“无脓毒性休克”。

### 临床边界

- 页面明确区分临床 VAP、NHSN VAE、CLABSI、CRBSI、CAUTI；
- CAUTI 文档及实现不再使用“至少两种菌”；
- PEEP/FiO₂ 缺失时不输出 VAC/IVAC/PVAP；
- qSOFA 不作为唯一诊断条件；
- 筛查线索不直接进入质控分子。

### 工程质量

- 科室权限、历史患者、外链访问均通过测试；
- 不存在患者循环 N+1；失败能降级为 `UNKNOWN/ERROR`；
- 审核写操作有审计和版本链；
- 单测覆盖设备日边界、去重、时间冲突、培养状态和 SOFA 变化。

## 13. 会签清单

### ICU / 院感 / 质控

1. CVC、PICC、透析导管、导尿管、气管插管、气切和无创通气的分类；
2. 每类设备日去重、episode 和统计周期；
3. 本院使用临床 VAP、NHSN VAE，或两套并行；
4. `quality_26` CRBSI 与 CLABSI 的关系；
5. CAUTI 症状、培养菌量和排除条件；
6. 脓毒症/脓毒性休克的人工确认角色与流程。

### 信息科 / ICU 系统厂商

1. `patient_tube` 与 `patient_tube_record/_item` 的真实关系；
2. 置入、拔除、删除、撤销和补录字段的权威含义；
3. PEEP、FiO₂、通气状态、呼吸道分泌物的编码和时间粒度；
4. LIS 培养、标本、菌种、菌量、药敏及真菌数据字段/取值；
5. 住院号、患者 ID、转科及重复入科的关联规则；
6. 是否允许医生库保存审核事件及其审计保留要求。
