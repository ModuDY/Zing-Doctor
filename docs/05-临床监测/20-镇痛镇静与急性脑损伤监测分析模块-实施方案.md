# 镇痛镇静监测与急性脑损伤神经功能监测分析模块
## 实施方案（沟通确认版，供 CodeBuddy / 豆包开发）

> 版本目的：把已沟通的产品方向、数据口径、分析能力、医疗安全边界和验收要求整理为可执行方案。本文是设计与实现约束，不代表已完成生产库复核或临床审批。
>
> **重要说明**：本文所列达梦数据量及样例来自现有数据盘点材料，实施前需用同一过滤条件复核；生产数据库只读访问，不在本项目新增评分录入或修改重症源数据。

---

## 1. 项目目标与已确认决策

### 1.1 目标

在重症医生决策系统新增两个独立的、以患者为中心的只读监测分析页面：

1. **镇痛镇静监测分析**：查看 NRS/CPOT、RASS、CAM-ICU 的当前记录、历史趋势和可选指标组合。
2. **急性脑损伤神经功能监测分析**：查看脑损伤诊断依据、神志、GCS、瞳孔、ICP 的记录、历史趋势和可选指标组合。

功能不止展示当前值，也须支持医生选择时间段、选择要共同观察的指标，分析患者在该时间窗内的变化。

### 1.2 已确认的产品决策

- 两个独立页面，不向患者诊疗摘要页继续堆叠卡片。
- 从患者工作台选定患者后可进入对应页面；从菜单直接进入时应先选患者，且遵守现有科室权限。
- 本系统只读重症监护系统数据；“记录评分”由重症监护系统完成。本系统不新增护理评分录入表单，不回写或修改源记录。
- 不做 AI 诊断、不自动下医嘱。提示只描述数据和变化，不代替医生判断。
- “自定义组合”一期限定为选择已有指标并共同展示，不支持自由编写公式、合成新临床评分或配置未经审批的临床阈值。

## 2. 数据来源与已知可行性

以下是现有盘点材料提供的数据情况，实施前要复核 SQL、过滤条件、字段映射和生产数据权限。

| 功能 | 权威/主要来源 | 已盘点项目 | 数据口径 |
|---|---|---|---|
| 疼痛、镇静、谵妄、GCS 评分及分项 | `control_doc`、`patient_doc_record`、`patient_doc_record_score` | `Z_ICU_SCORE_NRS`、`Z_ICU_SCORE_CPOT`、`Z_ICU_RASS`、`Z_ICU_ZWPF_CAM`、`Z_ICU_GCS` | 评分按 `doc_code` 区分；时间、人、审核状态优先取文书主记录；分项从 `score_json_value` 解析 |
| 高频神志 | `patient_observe_module_item_record` | `oi_shenzhi` | 代码 1–10，须按配置映射为文字和类别，不能把所有编码当线性严重度 |
| 双侧瞳孔 | observe 表 | `oi_tkz`、`oi_tky` | 大小与对光反射分别解析；“不规则/无法观察”等非数值须保留语义 |
| ICP | observe 表 | `oi_lny` | 数值及采集时间；无记录不能直接断言未监测 |
| 疼痛总分镜像 | observe 表 | `oi_ttpf` | NRS/CPOT 混合镜像，不能单独用于区分量表或国家质控统计 |

现有材料报告近 30 天文书记录约 62,661 条、评分明细约 62,599 条，且声称主表与明细 1:1。**这两组总数不相等，必须先以相同时间窗、删除状态、文书编码和审核状态复核，未解释差异前不得把 1:1 当作已证实约束。**

### 2.1 当前未确认的数据

- **VAS**：未确认生产库存在独立、实际使用的 VAS 文书编码；未核实前不在页面宣传支持 VAS。
- **独立肢体活动/肌力评估**：尚未确认对应数据项。GCS 的 M 项不是独立肢体活动或肌力记录，不可代替。
- MAP、CPP、药物实际执行记录、呼吸频率及 SpO₂ 与评估时间的可靠配对：后续联动前需另做数据盘点。
- CPOT `item4`、`item5`、`item60` 的源配置与选项中文映射：需用重症系统配置或护理部确认，不能仅凭样例推断。
- `patient_doc_record` 的 `(patient_id, doc_code, record_time)` 索引及主表/明细的缺失、撤销、审核口径：实施前核查。

## 3. 页面与分析功能设计

### 3.1 两页通用分析控件

每页均提供：

- 患者身份区：姓名、床号、住院号、科室、当前住院/ICU episode；按现有产品规范展示必要信息。
- 时间范围：默认近 24 小时；快捷项建议近 72 小时、7 天、30 天；支持自定义起止时间。查询须限制在有权限的患者和住院 episode 内。
- 指标选择：允许选择本页已支持的指标组合，并共同查看趋势；每条数据保留独立的采集时间、评估人和数据来源。
- 图表与记录明细联动：点选图表数据点能定位对应记录；提供可追溯的记录列表/表格。
- 缺失区分：时间窗内无记录、客观无法评估、不适用、部分字段缺失、数据源查询失败必须区分，不能把缺失展示成正常。

首版自定义范围建议最多 30 天；若患者住院时间更长，只有在单患者查询性能通过测试后才放开更长范围。禁止对 observe 大表做无患者条件或无时间窗的全局扫描。

### 3.2 镇痛镇静监测分析页

#### 当前数据区

- 疼痛：显示最新 NRS 或 CPOT、量表类型、总分、记录时间、评估人。CPOT 可展开四个维度及其原始选项；维度缺失时标明部分数据缺失。
- 镇静：显示最新 RASS 分值、分级文字、记录时间和评估人。没有患者个体化目标 RASS 时，不判定“达标/不达标”或“过度镇静”。
- 谵妄：显示源系统 CAM-ICU 原始结果及记录时间、评估人；另展示该记录是否满足评估条件的提示（见第 4 节）。源结果和本系统提示不可互相覆盖。

#### 趋势与组合分析

- NRS 与 CPOT 使用独立曲线/图层，禁止直接合并成同一连续量表或计算混合均值。
- 可选组合：NRS、CPOT、RASS、CAM-ICU；若选择多个指标，在共同时间轴展示，但用独立坐标或分类轨道，避免量纲误导。
- CAM-ICU 以阳性/阴性/无法评估等分类事件展示，不作为连续数值计算均值。
- 仅对同一种、可比较的数值评分展示最小值、最大值、记录数等描述统计；不对不同量表或类别变量求平均。
- 用户可以临时选择指标组合；如需保存个人视图，优先复用现有用户偏好机制。不得把视图配置写入患者临床记录表。

#### 量表适用性

量表选择取决于患者能否可靠自我报告疼痛，**不能仅由是否机械通气决定**。能够可靠沟通的插管患者也可能使用 NRS；无法自述时再使用 CPOT 等行为量表。页面显示呼吸支持状态可以作为背景，但不得用它单独替医生判定量表错误。

### 3.3 急性脑损伤神经功能监测分析页

#### 患者识别与诊断依据

- 展示命中的诊断名称、ICD 编码、诊断类型、诊断时间及来源。
- 一期可从已核实且符合“当前有效诊断”口径的 I60/I61/I62/I63/S06 等范围起步；排除个人史、后遗症、陈旧/恢复期和鉴别诊断。
- **G45/TIA 是否计入急性脑损伤及 ICU-18 分母需先对照国家指标定义和临床口径确认**，未确认前不纳入正式国家指标计算。
- 颅内感染、脑肿瘤、癫痫、心肺复苏后/缺血缺氧性脑病、其他代谢性脑病及影像异常等未完成数据映射前，不宣称识别了全部急性脑损伤患者。

#### 当前数据区

- 神志：显示映射后的文字、原始代码、记录时间和评估人。
- GCS：展示 E/V/M 分项、源记录总分；语言项 VT 标为“不可评”，例如显示“3T（E1、V-NT、M2）”。3T 不当作普通可比较的 3 分，不自动反哺 SOFA。
- 瞳孔：左右分别显示大小与对光反射；同时呈现左右差、相对患者自身历史基线变化。异常阈值未经临床批准前只显示事实，不触发硬预警。
- ICP：仅有记录时展示数值和趋势；无记录时按证据显示“未记录/状态未知/不适用”，不得填 0 或直接显示“未监测”。
- 独立肢体活动/肌力：数据源未核实前不显示为已支持指标，不用 GCS M 项冒充。

#### 趋势与组合分析

- 指标选择：神志、GCS 总分与 E/V/M、左/右瞳孔大小及反射、ICP；未来只有在源字段和时间口径核实后，才加入肢体活动、MAP/CPP 等。
- 数值指标用趋势图；神志、对光反射等分类指标用状态轨迹/事件标记。不得对分类编码简单连线并暗示等距严重度。
- GCS、瞳孔、神志和 ICP 可在同一时间轴组合观察，但必须分别呈现各自的真实记录时间。不同时间点不得被描述为“同一时刻综合评估”。
- 不做无证据插值，不把最近记录复制到之后的时间点；无数据区间明确留白/标缺失。

## 4. 医疗安全与判读规则

### 4.1 CAM-ICU 与 RASS

- 按 CAM-ICU 工具说明，RASS **-4 或 -5** 时通常为无法评估（UTA）；RASS -3 不应被方案写成自动 UTA。上线前按官方评估流程复核并统一实现口径。
- 需要明确 CAM 与 RASS 的配对策略：使用 CAM 评估之前、且处于经临床确认的有效时间窗内的 RASS。RASS 缺失、过旧或配对不明确时，CAM 可评估性显示 UNKNOWN/需核对，不推断为 UTA 或阴性。
- 如源系统录入“无谵妄”但同一有效评估时点 RASS 为 -4/-5：**保留源系统原始结果**，另显示“按评估条件该结果不宜作为有效阴性，建议核查”。不得静默把原始阴性覆盖为 UTA。
- UTA 不计作 CAM 阴性或阳性；不能据此改写源系统数据。

### 4.2 其他临床提示边界

- NRS≥4、CPOT>2、瞳孔差值、ICP 15、神志变化等均先作为候选规则；需科室批准、参数化、形成验收记录后才可启用提醒。
- BTF 的 ICP >22 mmHg 处理阈值限于相应重型 TBI 语境，不可泛化到脑梗死、脑出血等所有脑损伤患者；本系统只作带适用范围的事实提示，不生成治疗指令。
- RASS 深镇静本身不代表过度镇静；缺少目标 RASS 时不判达标与否。
- GCS 下降提示须要求前后记录可比较；插管、肌松、镇静显著变化等可能影响比较，应显式注明或暂不触发自动变化结论。
- 所有规则展示：判定依据、涉及记录、时间、评估人和阈值版本；临床人员负责诊断与处置。

## 5. 数据状态与来源要求

建议每个指标独立返回状态，至少支持：

| 状态 | 含义 |
|---|---|
| `FOUND` | 查询成功且记录有效 |
| `PARTIAL` | 有总分或部分维度，但分项/必要字段缺失 |
| `NOT_RECORDED` | 查询成功，限定时间窗内没有应有记录 |
| `UNABLE_TO_ASSESS` | 源记录或评估规则明确无法评估，如 CAM-ICU 的符合条件 UTA、GCS 语言项 VT |
| `NOT_APPLICABLE` | 根据已核实适用条件，该指标不适用于此患者/场景 |
| `UNKNOWN` | 查询失败、超时、权限或数据源异常，不能解释成无数据 |

单条数据需能追溯：`source`、文书/记录 ID（若接口允许）、指标编码、原始值、解析值、采集/记录时间、记录人、审核状态。原始值不可被派生值覆盖。

数据源原则：

1. 国家质控及量表分项以 doc 三表为准。
2. 高频神志、瞳孔、ICP 使用 observe 表。
3. observe 镜像仅作趋势补充；不能将 doc 与 observe 直接 `UNION` 后重复计数。没有稳定事件关联键时，使用明确的优先级/回退策略，不凭时间和值相等就认定同一事件。
4. 任何一类数据源失败只影响对应区块/指标，不能把整页其他成功区块一并变成空数据。

## 6. 质控统计范围

拟统计 ICU-09（镇痛评估率）、ICU-10（镇静评估率）、ICU-18（急性脑损伤患者意识评估率）以及本院 CAM 覆盖率等。

正式开发质控报表前必须：

- 将国家 2024 版原文中的指标名称、分子、分母、统计周期、排除条件落入配置/说明，并由产品和临床负责人核对；不得仅凭本方案中的摘要文字实现。
- 明确以患者人数还是住院/ICU episode 去重，以及跨月、转科、重复入科、出科患者的处理；与现有质控看板口径一致。
- 明确 `del_flag`、撤销/作废、补录、审核状态及缺评分明细记录的统计规则。
- ICU-18 分母覆盖未完整验证前，只能标为“本系统当前可识别病例的监测覆盖情况”，不得标成完整国家级 ICU-18 指标。
- CAM 覆盖率/阳性率/UTA 率属于本院分析项，不冠以国家指标编号。

## 7. 技术实现约束

- 遵守项目当前 Vue3/Vite/Element Plus、Spring Boot、达梦与 MariaDB 双适配、路由/菜单/外链注册、统一响应结构等现有实现规范；开发前先查已有患者上下文、权限、图表组件和接口模式，禁止另造一套认证或页面壳。
- 后端按单患者、住院 episode、指标编码集合、明确时间窗批量查询；禁止逐指标逐患者 N+1，禁止大表全院无时间窗扫描。
- 查询前复核索引；observe 已盘点索引不代表线上执行计划必然命中，doc 索引仍需检查。通过达梦实际执行计划和响应耗时验证。
- 患者和科室权限必须在服务端校验，复用 `UserDepartScopeService` 等现有能力；不得信任前端传来的 `departCode` 或患者 ID。外链访问遵循既有来源科室边界。
- doc、observe 双源失败/超时分别处理；设置合理超时，支持区块级重试/错误状态。
- 用户选择时间范围与指标组合的接口必须受最大范围、患者权限和 SQL 参数绑定保护；不能拼接未校验的列名或表名。
- 如果持久化个人图表配置，只能存配置，不存/改临床评分；确认现有偏好机制和授权后再做。无现成机制时一期先提供页面内临时选择。
- 图表须正确处理负数 RASS、分类指标、VT、null、重复时间戳、乱序记录、跨日、时区和空数据。

## 8. 分期实施与交付物

### 阶段 0：数据口径复核（开发前置）

产出：字段/编码映射表、同条件 SQL 样例与结果、索引/执行计划、脏数据清单、未确认项。

必须核对：文书主从数量差异；审核/作废过滤；CPOT item 映射；CAM-RASS 配对；诊断编码与诊断类型；VAS、肢体活动等项目是否存在。

### 阶段 1：镇痛镇静监测分析页（只读）

交付：NRS/CPOT/RASS/CAM 当前记录、分项、状态；自定义时间范围；多指标组合趋势；明细下钻；CAM 原始结果与可评估性提示并存。阈值确认前不启用疼痛不足或过度镇静硬预警。

验收：选取真实患者，将页面记录与重症系统原始文书逐条比对；检查同一评估没有因 doc/observe 镜像重复出现。

### 阶段 2：急性脑损伤神经功能监测分析页（只读）

交付：诊断依据/分型、神志、GCS E/V/M、双侧瞳孔、ICP 状态与趋势、可选指标组合。

验收：脑损伤患者识别名单由临床人员抽样核对假阳性/假阴性；确认既往史、鉴别诊断、陈旧性诊断被排除；未识别的数据范围明确说明。

### 阶段 3：评估质量与质控

交付：经原文核实后的 ICU-09/10/18 及本院 CAM 分析；患者级覆盖率和下钻明细。

前置：episode、统计周期、去重、审核/撤销规则及 ICU-18 分母映射经临床/质控部门签字确认。

### 阶段 4：后续联动（单独评审）

疼痛/镇静评分与药物**执行记录**、SAT/SBT、生命体征、呼吸抑制风险等。须先确认数据源、时间对齐与临床规则；不得由医嘱开立记录冒充给药执行，不自动下医嘱。

## 9. 验收清单

### 产品与分析

- [ ] 两个独立页面，无新增摘要卡片；患者上下文与返回工作台路径正常。
- [ ] 默认和快捷时间范围、自定义起止时间正常；时间范围不可越过患者 episode 或授权范围。
- [ ] 可选择多个已有指标共同分析；NRS/CPOT 分开，分类指标不按连续变量统计。
- [ ] 图表、明细、时间、评估人、数据来源可追溯；缺失不插值、不显示为正常。
- [ ] 视图配置不写入临床记录表。

### 临床口径

- [ ] CAM 的 RASS -4/-5 UTA 规则正确，RASS -3 不被自动判 UTA；源 CAM 与系统提示并存。
- [ ] NRS/CPOT 适用性不只由机械通气状态决定。
- [ ] 3T 的 VT 不作为普通数值比较；不自动反哺 SOFA。
- [ ] ICP 阈值不泛化；任何候选提醒均有科室审批记录。
- [ ] ICU-18 识别范围不完整时不展示为完整国家指标。
