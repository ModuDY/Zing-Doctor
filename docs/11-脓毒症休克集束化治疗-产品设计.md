# 脓毒症休克集束化治疗（Sepsis Bundle）· 产品设计方案

> 版本：设计稿 v1 · 2026-09-13
> 变更：2026-09-15 —— ① 感染部位 / 致病菌 / 抗菌药物改为**医生多选枚举**入库，系统自动取到的原始值降级为「系统参考」小字（不入库）；② 三块参考值的取数窗口收窄为「本条评估记录创建时间往前 14 天」；③ 页面版式改为 SOFA / APACHE II 同款（左侧评估记录列表 + 右侧内容区）
> 定位：围绕 **Sepsis-3** 定义与 **1H / 3H / 6H 集束化治疗（Bundle）** 要求，自动从 ICU 业务数据中提取证据、判定每一项是否达标，把「指南要求」变成可核查的清单，降低脓毒症/感染性休克患者的救治延迟。

## 一、背景与定位

### 1.1 解决什么问题

- 集束化治疗要求「1 小时内测乳酸、抗菌药前留血培养、用广谱抗菌药、低血压/乳酸≥4 时 30ml/kg 晶体液、液体复苏后仍需去甲肾上腺素维持 MAP>65」等，**条目多、时间窗紧**，人工核对易漏项。
- 事后质控依赖翻病历，**无法在床旁实时提示**。
- 因此本模块的做法是：**自动评估 + 人工修正 + 多次评估留痕**。

### 1.2 设计原则

1. **自动评估只做「有证据就判达标」，无证据不判达标**（保守原则，避免虚高完成率）。
2. **人工修正永久保留**：医师手动勾选的状态优先于自动评估结果（`restoreManualStatus`）。
3. **多次评估留痕**：每次保存都是新记录，可对比不同时点评估结果；页面**左侧评估记录列表**（与 SOFA / APACHE II 一致）可切换查看、新建、逐条删除。
4. **医生勾选优先于自动值**：感染部位 / 致病菌 / 抗菌药物三块由医生**点选枚举**入库（多选，以「、」拼接）；系统按 14 天窗口自动取到的原始药名 / 菌名仅作「系统参考」小字展示，**不入库**。未勾选则存空串。

## 二、功能清单

| 功能 | 说明 |
|---|---|
| 患者集束化详情 | 按住院号拉取患者，自动判断 1H/3H/6H 各项目完成情况 |
| 感染信息录入 | 感染部位 / 致病菌 / 抗菌药物三块为**医生多选枚举**入库；同时展示 14 天窗口内系统自动取到的原始值作为「系统参考」（不入库） |
| 液体复苏未达标原因 | 自动识别容量过负荷、器官损伤等禁忌原因 |
| 多次评估记录 | 左侧历史评估列表（形同 SOFA / APACHE II），可切换查看、新建、逐条删除 |
| 人工修正 | 每个条目可手动勾选/取消，保存后优先于自动结果 |
| 抗菌药识别词库 | 白名单（广谱抗菌药）+ 黑名单（非抗菌药）可配置，配置即生效 |

## 三、判定规则

### 3.1 关键时间基点

| 时点 | 取值规则 |
|---|---|
| 入科时间 `inDepartTime` | `patient_info.in_depart_time` |
| 出科时间 `outDepartTime` | `patient_info.out_depart_time` |
| **确诊时间 `diagnosisTime`**（所有时间窗的起点） | ① 优先用已保存记录的 `diagnosis_time`；② 否则在诊断列表中找 `diag_name` 含「脓毒症 / 感染性休克 / 脓毒性休克 / 败血症 / 脓毒血症 / sepsis / Sepsis」的诊断，取 `diag_time`（为空回退 `create_time`），且**必须落在「入科后 ~ 出科前」**区间；③ 仍找不到则用**入科时间**；④ 都没有则用当前时间 |

时间窗：1H = 确诊 + 1h；3H = 确诊 + 3h；6H = 确诊 + 6h。

### 3.2 休克类型判定（`determineShockType`）

只取「入科后 ~ 出科前」的诊断，优先级：**感染性休克/脓毒性休克 > 脓毒症**，都没有返回空串。命中即写回 `shockType`。

### 3.3 1H 项目

| 项目 | 自动判定规则 |
|---|---|
| 测量乳酸 | 确诊后 1h 内存在乳酸检验结果 → 达标，并记录**第一条**乳酸值与时间 |
| 乳酸动态监测 | 初始乳酸 **> 2.0 mmol/L** 时，1h 之后仍有乳酸检验 → 达标，并记录次数 |
| 抗菌药前留取血培养 | 存在血培养记录且**首次血培养时间 ≤ 首次抗菌药开始时间** → 达标（同时记录两者时间）；只有血培养无抗菌药记录时也判达标 |
| 应用广谱抗菌药 | 1h 内存在命中**广谱白名单**的抗菌药医嘱 → 达标，记录药名 |
| 低血压或乳酸 ≥ 4 | 乳酸 **≥ 4.0 mmol/L** → 标记 `hypotensionOrLactateHigh`（用于触发液体复苏核算） |
| 30ml/kg 晶体液复苏 | 目标量 = **30 × 体重(kg)**；实际量 = 确诊~1h 内**单位为 ml/mL** 的晶体液医嘱剂量之和；实际 ≥ 目标 × **0.9**（允许 10% 误差）→ 达标 |
| 去甲肾上腺素维持 MAP > 65 | 血管升压药医嘱中存在名称含「去甲肾上腺素」→ 达标，记录剂量+单位 |

### 3.4 3H 项目

| 项目 | 规则 |
|---|---|
| 监测乳酸 | 确诊后 3h 内存在乳酸检验 → 达标 |
| 抗菌药前留取血培养 | 复用 1H 结论 |
| 使用广谱抗菌药 | 复用 1H 结论 |
| 30ml/kg 液体复苏 | 若 1H 已触发低血压/高乳酸且已知体重：按「确诊 ~ 3h」窗口重新累计晶体液并核算（同样 0.9 系数）；未触发则复用 1H 结果 |
| 3h 后乳酸复查值 | 取 3h 之后**最新一条**乳酸值 |
| 监护数据（3H~6H 窗口） | `CVP`（名称含 CVP）、`MAP`（名称含「平均压」）、`ScvO2`（含 ScvO2/中心静脉血氧饱和度），各取窗口内**第一条**非空值 |
| 尿量 | 确诊 ~ 3h 内名称含「尿量」的记录求和，> 0 才展示 |

### 3.5 6H 项目

| 项目 | 规则 |
|---|---|
| 血管升压药维持 MAP ≥ 65 | 存在任意血管升压药医嘱 → 达标，记录首个「药名 + 剂量 + 单位」 |
| 重新评估容量状态与组织灌注 | 6h 内乳酸测量次数 **≥ 2**，或存在血管升压药 → 达标 |
| 早期乳酸升高时重复测量 | 初始乳酸 > 2.0 且 6h 内乳酸次数 ≥ 2 → 达标 |
| 6h 内最新乳酸值 | 取 6h 内最后一条乳酸结果 |

### 3.6 抗菌药物识别（白名单 + 黑名单双重保险）

```
antibioticList = 医嘱
    .filter(命中 broad_spectrum 白名单)
    .filter(!命中 non_antibiotic 黑名单)
```

- **必须用白名单**：中药、营养药、解热镇痛药等非抗菌药有数千种，黑名单永远列不全。
- 词表来源：`config_abx_word` 表（`broad_spectrum` / `non_antibiotic` 两类）；**每次评估前刷新**，配置页修改即时生效；表为空时回退代码内置默认词表（广谱 60+ 药名、非抗菌药 500+ 关键词：电解质、维生素、营养、抑酸、镇静镇痛、肌松、抗凝、血管活性、抗心律、利尿、化痰、造影剂、激素、血制品、降糖降脂、抗组胺、精神药物、外用消毒、中药等）。
- 「广谱」= 药名**包含**白名单关键词（包含匹配，兼容商品名/溶媒复合名）。
- ⚠️ 该判定链只服务 1H/3H/6H 的**项目达标判定**，取数**不受** 14 天窗口限制；另有一份收窄到 14 天窗口的抗菌药列表专供「系统参考值」，见 §3.10。

### 3.7 感染部位自动判断（→ 现仅作「系统参考」）

诊断名称按**关键词映射表**（`INFECTION_SITE_MAP`）归一化到 12 个部位：肺部感染、血流感染、CRBSI 血流感染、非 CRBSI 血流感染、中枢神经系统感染、腹腔感染、胆道感染、胃肠道感染、泌尿系感染、骨髓感染、皮肤软组织感染、其他部位感染。多条命中用「、」拼接。映射时**按声明顺序**匹配，`脓肿` 兜底放最后（避免把「肝脓肿」误判为皮肤软组织感染）。

> ⚠️ 2026-09-15 起：该结果**不再入库**，仅作为页面「系统参考」小字展示（字段 `infectionSiteRef`）；入库的 `infection_site` 只存医生在枚举按钮上勾选的值。取数范围收窄为「本条评估记录创建时间往前 14 天」（见 §3.10）。

### 3.8 致病菌自动填充（→ 现仅作「系统参考」）

从细菌培养结果中取 `bacteria_name`，经 `isValidBacteriaName` 过滤后去重拼接：

- 排除「未检出 / 阴性 / 无细菌 / 正常菌群 / 无致病菌 / 未见致病菌」；
- 排除形如「培养 X 天未检出…」的描述（正则 `.*\d+.*天.*`）；
- 排除「生长」且同时含「杂菌 / 正常 / 无 / 未」的笼统结果。

> ⚠️ 2026-09-15 起：结果写入 `pathogenRef` 仅作「系统参考」展示，**不再入库**；入库的 `pathogen` 只存医生勾选的枚举值。培养取数窗口由「确诊时间 ± 30 天」收窄为「本条评估记录创建时间往前 14 天」（见 §3.10）。

### 3.9 液体复苏未达标原因

| 原因 | 自动判定 |
|---|---|
| 容量过负荷 | 诊断含「肺水肿 / 急性左心衰 / 容量过负荷」 |
| 器官损伤 | 诊断含「AKI / 急性肾损伤 / ARDS / 急性呼吸窘迫」 |
| 毛细血管渗漏 | 当前固定为 false（预留） |

### 3.10 感染相关信息：医生勾选 + 系统参考（**2026-09-15 新增口径**）

| 块 | 入库字段（医生勾选） | 参考字段（系统自动，不入库） | 枚举项数 |
|---|---|---|---|
| 感染部位 | `infection_site` | `infectionSiteRef` | 12（血流感染 / CRBSI 血流感染 / 非 CRBSI 血流感染 / 肺部感染 / 腹腔感染 / 泌尿系感染 / 中枢神经系统感染 / 胆道感染 / 胃肠道感染 / 骨髓感染 / 皮肤软组织感染 / 其他部位感染） |
| 致病菌 | `pathogen` | `pathogenRef` | 10（鲍曼不动杆菌 / 绿脓杆菌 / 大肠杆菌 / 肺炎克雷伯菌 / 嗜麦芽窄食假单孢菌 / MRSA / 屎肠球菌 / 粪肠球菌 / 念珠菌 / 其他院内感染致病菌） |
| 抗菌药物 | `antibiotic` | `antibioticRef` | 18（青霉素类 / 第一代~第四代头孢菌素类 / β-内酰胺类 / 碳青霉烯类 / 氨基糖苷类 / 大环内酯类 / 喹诺酮类 / 糖肽类 / 磺胺类和甲氧苄啶 / 林可酰胺类 / 四环素类 / 酰胺醇类 / 硝基咪唑类 / 抗真菌药物 / 其他抗菌药物） |

**取数窗口（仅作用于三个 `*Ref` 参考值）**

```
refEnd   = 本条评估记录的 create_time（新建评估时 = 当前时间）
refStart = refEnd - 14 天
```

- 窗口起止经 `refWindowStart` / `refWindowEnd` 回传前端，展示在「感染相关信息」卡标题右侧，便于医生判断参考值的新旧。
- ⚠️ **同一患者不同批次评估的窗口会随各自 `create_time` 漂移**——第 N 次与第 N+1 次评估看到的参考值不一定相同。这是刻意口径（反映"评估当时能看到的数据"），不是缺陷。
- ⚠️ **1H / 3H / 6H 的达标判定不受此窗口影响**：乳酸、血培养、晶体液、升压药等仍按各自「确诊 + 1h/3h/6h」窗口取数；抗菌药医嘱也只把「参考值」那份收窄到 14 天，判定用的 `antibioticList` 保持全量。
- 医生未勾选任何枚举项时，入库字段存**空串**；已保存值回填勾选态时，只保留仍在枚举表内的值，避免历史脏数据变成幽灵选中。

**为什么这样改**：自动取到的原始药名/菌名带商品名、溶媒复合名、培养描述残留，直接入库会污染质控统计；改为医生勾选标准枚举后下游统计口径稳定，原始值退居「核对参考」。

| 数据 | ICU 表 | 方法 |
|---|---|---|
| 患者基本信息 | `patient_info` | `selectPatientByInHospitalNo` |
| 诊断列表 | `patient_info_diagnosis` | `selectDiagnosis(inHospitalNo)` |
| 乳酸检验 | `patient_info_lis_item`（乳酸项目） | `selectLactateResults(inHospitalNo)` → `check_time / result` |

| 抗菌药 / 晶体液 / 血管升压药医嘱 | `patient_advice` | `selectAntibioticAdvice` / `selectFluidAdvice` / `selectVasopressorAdvice` → `name / start_time / drug_one_dosage / drug_one_dosage_unit`（**判定用，全量**） |
| 抗菌药医嘱（**参考值专用**） | `patient_advice` | `selectAntibioticAdvice(inHospitalNo, refStart, refEnd)` + 白/黑名单过滤 → 仅用于 `antibioticRef`（14 天窗口，见 §3.10） |
| 细菌培养结果（**致病菌参考值**） | 微生物结果视图/表 | `selectBacteriaCultureForStats(refStart, refEnd, "")` 后按住院号过滤 → `bacteria_name`；窗口 = 评估记录创建时间往前 14 天（原为 `diagnosisTime ± 30 天`） |
| 监护数据（CVP/MAP/ScvO2） | `patient_observe_module_item_record` + `patient_observe_module_item` | `selectObserveRecords(patientId, start, end)` → `item_name / item_value` |
| 尿量 | `patient_io_module_item_record` + `patient_io_module_item` | `selectIoRecords(patientId, start, end)` → `item_name 含"尿量"` |

`zing_doctor_db_prod.patient_doc_sepsis_bundle_record`

词库配置表：`config_abx_word`（`word_type` = `broad_spectrum` / `non_antibiotic`，含启用标记与关键词），由「抗菌药物识别词库配置」页维护，参考 `14-抗菌药物识别词库配置-产品设计.md`。

## 八、风险与已知限制

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | 「30ml/kg 达标」允许 10% 误差，且只累计**单位为 ml/mL** 的医嘱 | 记录单位不规范时低估复苏量 | 优化单位归一化（袋/瓶×规格） |
| 2 | 3.4 中「监护数据取窗口内第一条非空」 | 若第一条是异常值，展示偏差 | 可改为取时间最靠近评估点的一条 |
| 3 | 「重新评估容量状态」用「乳酸次数 ≥2 或有升压药」近似 | 可能虚高 | 后续接入容量评估文书 |
| 4 | 确诊时间依赖诊断名称关键词 | 诊断命名不规范（如「脓毒血症休克」）时回退入科时间，时间窗整体偏移 | 维护诊断关键词字典 |
| 5 | 抗菌药识别依赖包含匹配词表 | 新药/商品名未入词库会漏判 | 定期用真实医嘱训练词库（已有配置页） |
| 6 | 尿量只取「确诊~3h」求和 | 与「3h 集束化」语义一致，但 1H/6H 无尿量口径 | 明确口径说明 |
| 7 | 记录以 `in_hospital_no` 为业务键 | 同一住院号多次入科会互相覆盖（取最近一条） | 可加 `patient_id` 维度 |
| 8 | 三块参考值窗口随评估记录 `create_time` 漂移 | 同一患者不同批次评估看到的参考值不一致 | 刻意口径（反映"评估当时可见的数据"）；页面已显式展示窗口起止，便于判断新旧 |
| 9 | 医生勾选枚举与系统参考值可能不一致 | 需人工判断采信哪一个 | 刻意保留：枚举保证统计口径稳定，参考值保留原始证据；两者同屏对照 |
