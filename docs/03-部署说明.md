# 部署说明

## 1. 环境依赖

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 8+（本机编译） | 服务器运行用 Docker JRE8 镜像 |
| Maven | 3.6+ | 构建后端 |
| Node.js | 18/20 | 构建前端 |
| Docker / docker-compose | 任意较新版本 | 生产部署 |
| 达梦数据库 DM8 | 服务器上 ICU 系统所在实例 | 主库（医生系统自有）+ ICU 只读库 |
| 达梦 JDBC 驱动 | 8.1.3.140 | 已随项目 `lib/` 目录打包（system scope） |

## 2. 数据库初始化

在达梦 DM8 中创建医生系统自有模式并导入脚本（目标实例与 ICU 系统共用，同实例不同模式）：

```bash
# 方式一：达梦 disql 命令行（推荐服务器执行，统一用 SYSDBA）
disql SYSDBA/Sa_20250815@100.120.1.102:14236
SQL> start /opt/zing-doctor/sql/00_init_user.sql   # 建模式 zing_doctor_db_prod（AUTHORIZATION SYSDBA）
SQL> start /opt/zing-doctor/sql/01_schema.sql      # 建表（11 张业务表，SQL 内显式模式前缀）
SQL> start /opt/zing-doctor/sql/02_seed.sql        # 初始化页面注册/DDD/MDRO/词库等种子数据
SQL> start /opt/zing-doctor/sql/03_icu_indexes.sql # （可选，建议）ICU 库只读查询性能索引
SQL> start /opt/zing-doctor/sql/05_apache2_pdf.sql # （老环境升级）APACHE II 评分 PDF 列，幂等
SQL> start /opt/zing-doctor/sql/06_abx_drug_dict.sql # 抗菌药物字典表（HIS 同步副本，只执行一次）
SQL> start /opt/zing-doctor/sql/07_sofa.sql        # SOFA 评分建表 + 页面注册 + 配置种子
SQL> start /opt/zing-doctor/sql/08_sofa_p1.sql     # SOFA 页面注册与列注释，幂等
SQL> start /opt/zing-doctor/sql/09_quality.sql     # 质控指标中台建表 + 页面注册，幂等
SQL> start /opt/zing-doctor/sql/10_quality_config.sql # 质控配置真源三表 + 注册 quality-config 页，幂等

# 方式二：达梦管理工具（DTS/数据库迁移工具）直接执行 sql/*.sql
```

### SQL 脚本清单

| 脚本 | 作用 | 是否必需 |
|---|---|---|
| `00_init_user.sql` | 建模式 `zing_doctor_db_prod` | 是 |
| `01_schema.sql` | 建 11 张业务表（页面配置、决策、DDD、MDRO、集束化、交班、APACHE II 等） | 是 |
| `02_seed.sql` | 页面注册 + DDD/MDRO/词库知识库种子数据（幂等，不重置后台配置） | 是 |
| `03_icu_indexes.sql` | ICU 库查询性能索引（不修改业务数据） | 建议 |
| `03_word_inc_v2319/23111.sql`、`04_abx_word_training.sql` | 抗菌药识别词库增量 | 按版本 |
| `05_apache2_pdf.sql` | APACHE II 评分 PDF 大字段列（老环境升级，幂等） | 升级时 |
| `06_abx_drug_dict.sql` | **抗菌药物字典**：建 `zing_abx_drug_dict`（HIS `config_drug` 抗菌药清单同步副本，供 `AbxDrugRecognizer` 精确匹配） | 使用抗菌药识别时 |
| `07_sofa.sql` | **SOFA 评分**：建 `sofa_score_record`（含文书 PDF 大字段 `pdf_data`/`pdf_name`）/ `sofa_config` 两表 + 注册 `sofa-score` / `sofa-overview` 页面 + 配置种子 | 使用 SOFA 功能时 |
| `08_sofa_p1.sql` | **SOFA P1**：PDF 两列的列注释 + 注册 `sofa-config` 配置管理页（幂等；**不含 ALTER**，两列已定义在 07 建表语句内） | 使用 SOFA 功能时 |
| `09_quality.sql` | **质控指标中台**：建 `quality_index` / `quality_calc_run` / `quality_metric_result` / `quality_calc_trace` / `quality_metric_patient` / `quality_monthly_report` 六表 + 注册 `quality-board` / `quality-monthly` 页面（幂等） | 使用质控功能时 |
| `10_quality_config.sql` | **质控指标可视化配置**：建配置真源三表 `quality_metric_def` / `quality_fact_def` / `quality_def_history` + 注册 `quality-config` 页面（幂等） | 使用质控「可视化配置」时 |

> `install.sh` 会自动执行 `06_abx_drug_dict.sql`、`07_sofa.sql`、`08_sofa_p1.sql`、`09_quality.sql`、`10_quality_config.sql`（三个初始化通道均已纳入）。
> ⚠️ 若为**已初始化过的老库**且服务器装有 `disql`，`install.sh` 会跳过整个建库步骤（检测到 `zing_page_config` 已存在即 return），此时需**手动执行** `06_abx_drug_dict.sql`、`07_sofa.sql`、`09_quality.sql`；`07`/`08`/`09` 幂等可重复运行，`06` 为 `CREATE TABLE`（**只执行一次**，重复执行会报表已存在，可先 `DROP TABLE` 或忽略该报错）。
> ⚠️ 漏执行 `06` 不会导致页面 500，但 `AbxDrugRecognizer` 词库刷新会持续告警 `无效的表或视图名[zing_abx_drug_dict]`，抗菌药识别降级为关键词匹配。
> ⚠️ 漏执行 `09` 会同时导致两个后果：**质控看板 / 月度汇总页直接报错**（`quality_index` 等表不存在），且 `quality-board` / `quality-monthly` 未登记进 `zing_page_config` → `/entry/...` 外链被判定为未注册页面而拒绝。
> ⚠️ 漏执行 `10` 会同时导致两个后果：**配置页保存时报「无效的表或视图名[quality_metric_def]」**，且 `quality-config` 未登记 → `/entry/quality-config` 外链返回 `{"code":404,"message":"未注册的页面：quality-config"}`。

> `zing_icu_db_prod` 为 ICU 系统既有模式，医生系统**只读**，**不要**在此初始化脚本中创建/修改。
> 医生系统统一用 `SYSDBA` 连接（与 ICU 系统访问方式一致），通过显式模式前缀访问 `zing_doctor_db_prod`、`zing_icu_db_prod` 两个模式。

## 3. 本地开发

### 后端（端口 8081）

```bash
# 修改 application.yml 中 doctor/icu 两个数据源连接信息
mvn spring-boot:run
```

### 前端（端口 5173，已配置 /api 与 /entry 代理到 8081）

```bash
cd frontend
npm install
npm run dev
```

### 联调外链

```bash
# 先生成一条外链 URL（mock 数据，示例患者 P1001/P1002/P1003）
curl "http://localhost:8081/api/external/token?pageCode=abx-patient-list&baseUrl=http://localhost:5173"
curl "http://localhost:8081/api/external/token?pageCode=abx-decision&baseUrl=http://localhost:5173&patientId=P1001"
# 浏览器打开返回的 URL 即可免登录进入对应页面
```

## 6. ICU 表结构接入（SQL 实现已就绪）

已基于 ICU 系统真实表结构实现 `SqlIcuPatientServiceImpl`（`@DS("icu")` 只读查询 zing_icu_db_prod），切换方式：

1. 在 ICU 数据源连接可用的前提下，设置 `zing.doctor.icu-data-provider=sql`（或环境变量 `ICU_DATA_PROVIDER=sql`）。
2. 重启后端，列表/评估数据改为真实 ICU 数据；`mock` 实现通过 `@ConditionalOnProperty` 自动停用。

### 表结构映射（第一维度）

| ICU 表 | 用途 | 取数要点 |
|---|---|---|
| `patient_info` | 患者信息/过敏史/体重/脓毒性休克/多耐药标记 | 在科 `is_in_depart=1`、未删除；`is_sepsis_shock` 休克；`multidrug_resistant_bacteria` 字典 1MRSA 2VRE 3CRE 4CR-AB 5MDR/PDR-PA |
| `patient_info_diagnosis` | 感染类型推断、真菌风险 | `diag_name` 关键词匹配（脓毒/肺炎/腹腔/血流/尿路/真菌） |
| `patient_info_lis_item` | 检验指标 PCT/WBC/CRP/肌酐/乳酸 + **微生物培养/药敏结果** | 检验指标按 `lis_item_name` 名称匹配取最新；微生物结果：`lis_item_name` 含 培养/药敏/涂片/镜检/菌 → `lis_item_result` 即**检出菌名或药敏结论**，按住院号查询 |
| `patient_observe_module_item_record` + `config_observe_item` | 体温 | 观察项记录 join 项目配置，`item_name LIKE '%体温%'` 或 `sign_code` 匹配 |
| `patient_advice_execute` | 当前抗菌药医嘱 | 执行中/未执行医嘱按抗菌药关键词过滤，取最早开始时间 |

### 微生物培养/药敏数据说明

- 数据位置：`patient_info_lis`（报告头，含标本类型 `lis_short_name`、报告名 `lis_name`、检查时间）与 `patient_info_lis_item`（结果明细）。
- 明细结果形态（实测样例）：`lis_item_name='细菌培养+药敏'` → `lis_item_result='鲍曼不动杆菌'`（结果值即菌名）；`'细菌（镜检）'`→`'2+'`；`'细菌培养+药敏(厌氧瓶)'`→`'奇异变形杆菌'`。
- 关联键：表结构上 `patient_info_lis.lis_code = patient_info_lis_item.lis_code`；实现按**住院号 + 微生物关键词**直接查明细（不依赖报告头关联，规避导出子集不一致），`LEFT JOIN patient_info_lis` 尽力带出标本类型。
- 用途：培养菌名驱动 `pastCultures`（既往培养）与 MDR/MRSA/真菌风险增强（如菌名含 MRSA/ESBL/鲍曼/铜绿/念珠菌等自动提升风险标记）。
- 药敏结论行（result 为 S/I/R 或 敏感/中介/耐药）解析为「标本 药敏：药物 → 结论」。

## 7. 交付包命名规范

统一格式（`<版本>` 取自 `pom.xml` 的 `<version>`，`<yyyyMMdd>` 为打包当天日期）：

```
zing-doctor-<版本>-<形态>-<yyyyMMdd>.tar.gz
zing-doctor-<版本>-<形态>-<yyyyMMdd>.zip
```

| 段 | 取值 | 说明 |
|---|---|---|
| `zing-doctor` | 固定 | 取自 `pom.xml` 的 `artifactId` / `<finalName>` |
| `<版本>` | 如 `1.0.0` | 与 `pom.xml` 的 `<version>` 保持一致；热修可加后缀，如 `1.0.0-hotfix1` |
| `<形态>` | `full` / `runtime` / `runtime-slim` | 见下表「形态对照」 |
| `<yyyyMMdd>` | 如 `20260911` | 打包当天日期（本地时区） |
| 扩展名 | `.tar.gz`（首选）/ `.zip` | Linux 部署用 `.tar.gz`（保留权限位与 UTF-8 文件名）；`.zip` 供 Windows 传输/解压 |

### 形态对照

| 形态 | 含后端源码 | 含 `tools/docker-compose` 离线二进制 | 适用场景 | 体积参考 |
|---|---|---|---|---|
| `full` | 是 | 是 | 需在服务器重建 / 归档；内网且无 compose 时 | ~62 MB |
| `runtime` | 否 | 是 | 纯部署；服务器**无** `docker compose` 且无外网 | ~62 MB |
| `runtime-slim` | 否 | 否 | 纯部署；服务器**自带** `docker compose`（推荐） | ~29 MB |

三种形态共存内容：`install.sh`、`docker-compose.yml`、`Dockerfile`、`README.md`、`app/zing-doctor.jar`、`frontend/dist/`、`frontend/nginx.conf`、`lib/`、`sql/`、`docs/`、`tools/db-init`（+ `db-init-classes`）。

- `full` 额外含：`src/`、`pom.xml`、`frontend/src` 及其开发配置（`package.json`、`vite.config.js` 等）。
- `runtime` / `runtime-slim` 一律剔除：源码与开发配置、`target/`、`logs/`、`node_modules/`。

### 命名示例

```
zing-doctor-1.0.0-runtime-slim-20260911.tar.gz
zing-doctor-1.0.0-runtime-slim-20260911.zip
zing-doctor-1.0.0-full-20260911.tar.gz
```

### 打包执行要点

1. **版本号必须与 `pom.xml` 的 `<version>` 一致**，避免出现「包名版本 ≠ 实际代码版本」。
2. 打包前先重建产物，确保包内是最新构建：
   ```bash
   mvn clean package                  # 后端 → 覆盖 app/zing-doctor.jar
   cd frontend && npm run build       # 前端 → 生成 frontend/dist
   ```
3. 压缩包内顶层目录固定为 `zing-doctor/`，解压后可直接 `bash install.sh`。
4. 同一天多次打包**直接覆盖同名文件**（以最后一次为准），不引入 `-v1/-v2` 之类后缀，避免线上取错包。
5. 交付前自检：包内含 `app/zing-doctor.jar` 与 `frontend/dist/index.html`；`runtime*` 形态内**不含** `src/`、`pom.xml`、`node_modules`。
6. `install.sh` 默认按「服务器自带 `docker compose`」工作；若目标服务器缺失，请改用 `runtime` 形态（包内自带离线 compose 二进制）。
