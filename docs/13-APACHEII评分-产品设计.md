# APACHE II 评分 · 产品设计方案

> 版本：设计稿 v1 · 2026-09-13
> 定位：面向 ICU 危重患者的**急性生理与慢性健康评分（APACHE II）**，自动从重症业务系统取数计算 A（年龄）/ B（慢性健康）/ C（GCS）/ D（急性生理 12 项），输出总分与**院内死亡风险预测**，并生成可归档的评分文书（PDF）。

## 一、背景与定位

### 1.1 解决什么问题

| 痛点 | 本模块的解法 |
|---|---|
| APACHE II 需手工查 12 项生理指标 + GCS + 年龄 + 慢性健康，耗时易错 | 一键「自动获取并计算」，从监护/检验/血气/系统 GCS 自动取数 |
| 最差值取值口径不统一（有人取最新、有人取最差） | 统一「**窗口内最差值**」，并在「来源」弹窗中展示趋势与选中点 |
| 死亡风险预测依赖查表，易算错 | 内置 Knaus 1985 logistic 回归公式，自动算死亡率 |
| 评分文书需手工誊抄进病历 | 一键生成 A4 评分文书（含院徽抬头），可预览、下载、入库归档 |

### 1.2 与其它模块的关系

| 模块 | 关系 |
|---|---|
| SOFA 评分 | 同源取数（监护/检验/GCS），文书版式一致；SOFA 用于动态器官功能，APACHE II 用于入科严重度分层与预后 |
| ARDS 监测 | 共用氧合指数/呼吸机参数数据源 |
| 交班览表 | APACHE II 高危患者（总分 ≥ 20）纳入交班关注 |

## 二、评分规则（APACHE II 标准）

### 2.1 A 项 · 年龄（`calcAgeScore`）

| 年龄（岁） | ≤44 | 45–54 | 55–64 | 65–74 | ≥75 |
|---|---|---|---|---|---|
| 分值 | 0 | 2 | 3 | 5 | 6 |

### 2.2 B 项 · 慢性健康（`chronicScore`）

| 参数 `chronicHealth` | 含义 | 分值 |
|---|---|---|
| `elective` | 择期手术后 | 2 |
| `nonoperative` | 非手术 / 内科患者 | 5 |
| `none` / 未传 | 不存在严重器官功能不全或免疫抑制 | 0 |

> 自动初评固定传 `none`（保守计 0 分），需医生复核后手工修正。

### 2.3 C 项 · GCS（`C = 15 − GCS`）

- GCS = E（睁眼 1–4）+ V（言语 1–5）+ M（运动 1–6），三项**评全**才计分；
- **仅当 GCS 落在 [3, 15]** 才按 `C = 15 − GCS` 计分（范围 0–12）；
- 缺评 / 未传 / 越界（含前端缺项误传 0、1、2）**一律按「未评估」计 0 分**；
- 设计意图：不允许只评部分维度就拼分，也杜绝 GCS < 3 时 C 被算成 13/14/15 这类超过规则上限的虚高分。

### 2.4 D 项 · 急性生理 12 项（`physiologyScore`）

| 指标 | 4 分 | 3 分 | 2 分 | 1 分 | 0 分 |
|---|---|---|---|---|---|
| 体温（直肠 ℃） | ≥41 | 39–40.9 | 32–33.9 / 30–31.9 | 38.5–38.9 / 34–35.9 | 36–38.4 |
| 平均动脉压（mmHg） | ≥160 或 ≤49 | 130–159 | 110–129 / 50–69 | — | 70–109 |
| 心率（次/分） | ≥180 或 ≤39 | 140–179 / 40–54 | 110–139 / 55–69 | — | 70–109 |
| 呼吸（次/分） | ≥50 或 ≤5 | 35–49 | 6–9 | 25–34 / 10–11 | 12–24 |
| 氧合（见下） | 见下 | 见下 | 见下 | 见下 | 见下 |
| 动脉血 pH | ≥7.7 或 <7.15 | 7.6–7.69 / 7.15–7.24 | 7.25–7.32 | 7.5–7.59 | 7.33–7.49 |
| 血钠（mmol/L） | ≥180 或 ≤110 | 160–179 / 111–119 | 155–159 / 120–129 | 150–154 | 130–149 |
| 血钾（mmol/L） | ≥7 或 <2.5 | 6–6.9 | 2.5–2.9 | 5.5–5.9 / 3–3.4 | 3.5–5.4 |
| 肌酐（mg/dL，急性肾衰 ×2） | ≥3.5 | 2–3.4 | 1.5–1.9 / <0.6 | — | 0.6–1.4 |
| 红细胞压积（%） | ≥60 或 <20 | — | 50–59.9 / 20–29.9 | 46–49.9 | 30–45.9 |
| 白细胞（×10⁹/L） | ≥40 或 <1 | — | 20–39.9 / 1–2.9 | 15–19.9 | 3–14.9 |
| （GCS） | — | — | — | — | 见 C 项 |

**氧合项分支（`calcOxygenScore`）**

| 条件 | 指标 | 4 分 | 3 分 | 2 分 | 0 分 |
|---|---|---|---|---|---|
| FiO₂ ≥ 50% | A-aDO₂ | ≥500 | 350–499 | 200–349 | < 200 |
| FiO₂ < 50% | PaO₂ | < 55 | 55–60 | — | > 70（61–70 为 1 分） |

> 若无法获知 FiO₂，按标准降级用 PaO₂ 分支判定（同时保留 PaO₂ 与 A-aDO₂ 两条曲线供复核）。

### 2.5 总分与死亡风险预测

```
总分 = A(年龄) + B(慢性健康) + C(GCS) + D(急性生理12项)

ln(R / 1−R) = −3.5174 + 总分 × 0.1467 + 0.6031 × [非手术 或 急诊手术] + 诊断权重
院内死亡率 = 1 / (1 + e^(−logit)) × 100%
```

- 公式来源：Knaus WA, et al. APACHE II. *Crit Care Med*. 1985；**方程中的分值必须是总分**（APS + 年龄 + 慢性健康），不是仅 APS；
- `0.6031` 仅在「非手术」或「急诊手术」时叠加（择期手术不加）；
- `诊断权重`（`diagnosisWeight`）为可选参数，用于按病种做校准（未填按 0）；
- 后端死亡率保留 1 位小数入库；页面展示统一保留 2 位小数。

### 2.6 风险分层与总览口径

| 项 | 口径 |
|---|---|
| 高危患者 | 总分 **≥ 20** |
| 评分分布 | 0–4 / 5–9 / 10–14 / 15–19 / 20–24 / 25–29 / 30+ |
| 平均总分 / 平均死亡率 | 区间内所有正常记录（`status=1`）的算术平均（后端 1 位小数） |

## 三、取数口径

### 3.1 取数窗口

| 场景 | 窗口 |
|---|---|
| 手工「自动获取并计算」 | 用户选择的区间：24 小时 / 48 小时 / 入科后 24h / 入科前 24h / 自定义 |
| 自动初评 | 入科时间（缺失则 `now − overHours`）→ 当前时间 |

**窗口内最差值策略**：每项生理指标取窗口内「偏离正常最远」的值（如心率取最高、MAP 取最低、pH 取离 7.33–7.49 最远者）。

### 3.2 各指标数据源

| 指标 | 数据源 | 说明 |
|---|---|---|
| 体温 / MAP / 心率 / 呼吸 / FiO₂ | `patient_observe_module_item_record` + `patient_observe_module_item` | 按 item_code（优先）/item_name 匹配 |
| pH / PaO₂ / PaCO₂ | 血气记录（`patient_info_lis_item` / 血气明细） | 按**采集时刻分组**，同一管血的 pH/PaO₂/PaCO₂ 配对 |
| FiO₂ 配对 | 监护记录 | 为每管血气**就近匹配**采集时刻最近的 FiO₂ |
| 血钠 / 血钾 / 肌酐 / 红细胞压积 / 白细胞 | `patient_info_lis_item` | 检验结果（肌酐按 mg/dL 统一，µmol/L 换算 ÷88.4） |
| GCS | 重症系统 GCS 文书（`Z_ICU_GCS`） | 取窗口内**评全且非插管的最新一条** |
| 年龄 / 性别 / 体重 | `patient_info` | — |
| 诊断 | `patient_info.diagnosis_content` / `patient_info_diagnosis` | 文书诊断行 |

### 3.3 GCS 同步

- 手工评分时，通过 `GET /api/apache2/patient/{patientId}/gcs-records` 拉取系统已评估的 GCS 记录供选择；
- 自动初评时，取取数窗口内**最新一条评全（非插管）**的系统 GCS 计入 C 项，并把 E/V/M 三项一并写入 `apsData`（否则医生打开记录时三项目空白，看上去像「没同步到」）。

## 四、自动初评定时任务

| 项 | 值 |
|---|---|
| 类 | `Apache2AutoScoreTask#autoGenerateForInDepart` |
| cron | `0 0 1,7,13,19 * * ?`（每 6 小时：01:00 / 07:00 / 13:00 / 19:00），可配 `apache2.auto-generate.cron` |
| 入科阈值 | `apache2.auto-generate.over-hours`，默认 24，`≤0` 回退 24 |
| 扫描对象 | `IcuPatientMapper#selectInDepartPatientsOverHours`：在科（`is_in_depart=1`、`status=1`、`del_flag=0`）且入科超过阈值小时数 |
| **幂等** | 该患者**已有任何正常评分记录**即跳过（一人一次，`scoreType='auto'`） |
| 建档内容 | `chronicHealth='none'`、`diagnosisType='none'`、`emergencySurgery=0`；APS 原始值落 `apsData` 供医生复核 |
| 返回统计 | `scanned / created / skipped / failed` 写入日志 |
| 手动触发 | `POST /api/apache2/auto-generate?overHours=24&departCode=`（幂等） |
| 失败处理 | 单次异常只记日志，不影响下一次调度 |

> **与 SOFA 的策略对比**：两者扫描 SQL、入科阈值、幂等粒度**完全一致**（均为「已有任何记录则跳过」= 一人一条）。差异仅在执行频率：APACHE II cron 默认 `0 0 1,7,13,19 * * ?`（每 6 小时一次，实际只有首次生效），SOFA cron 默认 `0 0 1 * * ?`（每天 01:00 一次）。
>
> ⚠️ 2026-09-15 起 SOFA 已由「每天一次」改为「终身一条」，与 APACHE II 对齐；相应地 SOFA 的「评分历史趋势」下线，ΔSOFA 仅在医生手动补评多条后才有值。

## 七、文书（PDF）方案

### 7.1 生成流程

```
前端渲染离屏 DOM（.report-page，宽 794px ≈ A4 96dpi）
  → html2canvas 截图（scale 2，useCORS 加载 /logo.png）
  → jsPDF 等比缩放到一页 A4（210×297mm）输出 base64
  → 与评分主体一起提交 /save（或先落库主体，再用 POST /record/{id}/pdf 补传）
```

> 主体先落库、PDF 后补传是刻意解耦：PDF 大字段（含 base64 图片）写入慢，失败时**不影响评分数据落库**。

### 7.2 文书版式

```
┌───────────────────────────────────────────────────────────────┐
│                    [院徽 60×60]  福州市第二总医院                │
│                                  福州市第二医院                  │
│                                福建省福州中西医结合医院           │
├───────────────────────────────────────────────────────────────┤
│                   危重患者 APACHE II 评分表                     │
├───────────────────────────────────────────────────────────────┤
│  姓名：×××   床号：×××   住院号：××××××   Fi：××   评分时间：×××  │
│  诊断：×××××××××××××××××××××××××××××××××××××××××××××××××××××× │
├───────────────────────────────────────────────────────────────┤
│  A 年龄 | B 慢性健康 | C GCS | D 急性生理（12 项逐项得分表）      │
│  …                                                            │
│  总分 / 预测死亡率                                              │
│  评分医师：×××                              评分时间：××××-××-××  │
└───────────────────────────────────────────────────────────────┘
```

- **院徽 + 三行院名抬头**与 SOFA 评分文书保持一致（`frontend/public/logo.png`）；
- 字体：标题黑体（`SimHei`），正文宋体（`SimSun`），A4 宽 794px 固定像素渲染，保证导出与预览一致。

## 十、关键实现细节与风险点

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | 氧合项依赖「FiO₂ 就近配对」 | 若 FiO₂ 记录稀疏，配对可能偏差 | 来源弹窗已展示 worstTime 供复核；可增加配对时间容差提示 |
| 2 | 肌酐单位换算（µmol/L ÷ 88.4） | 单位识别错误会导致分值偏差 2 分 | 校验单位字段，异常单位不入计算 |
| 3 | 急性肾衰「×2」需医生判断 | 自动初评无法判定，会低估 | 自动初评标注「肌酐未按急性肾衰加倍」 |
| 4 | B 项慢性健康自动初评固定 `none` | 低估 B 项分值（0 vs 2/5） | 医生复核；后续可从诊断/免疫抑制用药自动识别 |
| 5 | GCS 未评估时 C 项按 0 分 | **低估**严重度（C 实际可能 0–12） | 页面已标「未评估」；建议提示医生补评 |
| 6 | 死亡率公式未按本院数据校准 | 绝对值仅供参考 | 定期用本院队列做校准（可配 `diagnosisWeight`） |
| 7 | 自动初评一人仅一次 | 入科早期生成的记录不会随病情更新 | 由医生手动补评（新建记录）；⚠️ SOFA 自 2026-09-15 起也已改为「终身一条」，不再提供按天建档参照 |
| 8 | PDF 以 base64 存 CLOB | 库表膨胀 | 建议改存对象存储，库内只留路径 |
| 9 | 院徽走 `/logo.png` 静态资源 | html2canvas 需允许跨域；同源部署无问题 | 建议内联 base64 或确保 `useCORS` |

## 十一、后续优化建议

1. B 项慢性健康自动识别（依据诊断 + 免疫抑制/器官功能不全用药）；
2. 自动判断急性肾衰并按标准对肌酐项加倍；
3. 增加 APACHE II 与 SOFA 的**同屏对比**与预后轨迹；
4. 文书支持电子签名与病案号归档；
5. 死亡率模型按本院数据重新校准（自定义系数可配）。
