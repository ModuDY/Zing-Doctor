## 2. patient_doc_record 索引（回应实施方案 §7）

实测索引仅 3 个，均为单列：
- INDEX33556859（id，主键）
- INDEX6923191908900（**patient_id**）
- INDEX6923208433400（doc_code）

**无 `(patient_id, doc_code, record_time)` 复合索引。**
- 单患者查询可命中 patient_id 单列索引（单患者各类文书全周期量级为几十至几百条），回表后再过滤 doc_code 与时间窗，性能可接受。
- 本系统对重症库**只读，不擅自建索引**；是否补复合索引由重症库 DBA 评估。
- 强制约束：所有 doc/observe 查询**必须带 patient_id + 时间窗**，禁止跨患者/全院扫描、禁止只按 doc_code 拉全表（doc_code 单列索引会扫全量表）。上线前用达梦实际执行计划与耗时复核。

## 4. CAM-ICU 与 RASS 配对实证（实施方案 §4.1，阈值修正）

**口径修正**：CAM-ICU 标准流程为 RASS **-4 或 -5（不可唤醒）时 UTA（无法评估）；RASS -3 仍可评估**。早期方案稿写"RASS≤-3 判 UTA"有误，正确为 **RASS∈{-4,-5} 才 UTA**。

患者黄萍（patient_id=2100967868254490626，机械通气）近 3 天 doc 记录：
- RASS：2026-10-07 19:00、19:15、21:00、10-08 10:00、21:00、10-09 09:00、21:00、10-10 08:00 **全部为 -4**；
- CAM-ICU：仅 2026-10-07 21:00 一条，源值"**无谵妄**"。

该 CAM 评估时点 RASS=-4，按评估条件**不能作为有效阴性**。处理遵循实施方案：**保留源系统原始值"无谵妄"，另显示"该时点 RASS=-4 深镇静，按 CAM-ICU 流程应为无法评估(UTA)，此阴性建议核查"，不静默覆盖、不计阴也不计阳**。
- 配对策略：取 CAM 评估时间**之前最近一次、且在临床有效时间窗内**的 RASS；RASS 缺失/过旧/配对不明确 → UNKNOWN/待核对，不推断 UTA 或阴性。有效时间窗具体分钟数需临床确认（建议同班次/评估前数小时内，参数化）。

## 5. CPOT 维度映射（实施方案 §2.1 未确认项，仍未闭环）

- CPOT 文书 score_json_value 实测字段：item1、item2、item3、item4/item5、item60、totalScore。样例：
  - `{"item1":"0","item2":"0","item3":"0","item4":"0","item60":"a","totalScore":"0"}`
  - `{"item1":"0","item2":"0","item3":"1","item5":"0","item60":"d","totalScore":"1"}`
- 表单字段配置表 `control_page_form_field`（列为 field_code/field_title/component_props）按"通气/发声/面部/肌紧/体动/表情/疼痛/item60/item4/item5"均**未命中**，即评分题目的中文与选项配置不在该表（可能在 control_doc_version 或前端表单配置中）。
- **结论：item1/2/3/4/5/60 与选项码 a/d 的权威中文映射未能从库中取得，需护理部或重症系统厂商确认。** 阶段 1 先按 CPOT 通用量表占位（item1 面部表情、item2 身体动作、item3 肌肉紧张、item4 通气顺应性[插管]/item5 发声[拔管]，item60 为该维度选项 a/d），并在页面标注"维度名称待护理部核对"，同时展示原始选项码，不臆断中文。
- CPOT 总分 0–8（四维度各 0–2）；NRS 0–10。阈值（CPOT>2、NRS≥4）均为候选，待科室批准后参数化。

## 6. 急性脑损伤识别口径（实施方案 §3.3）

- 一期纳入现患、急性：I60（SAH）、I61（脑出血）、I62（其他非创伤出血）、I63（脑梗死）、S06（创伤性颅脑损伤）。
- 排除：I69（后遗症/陈旧/恢复）、Z86.7（个人史）；diag_type_name 排除"鉴别诊断"。
- **G45/TIA：国家 ICU-18（2024 版）列举的急性脑损伤为"创伤性颅脑损伤、脑梗塞、蛛网膜下腔出血、脑出血、颅内感染、脑肿瘤、癫痫 + 心肺复苏术后/缺血缺氧性脑病/热射病及代谢性、肝性、肺性、肾性脑病 + 影像异常"，未明确列入 TIA/G45。** 按实施方案，G45 一期**不纳入**正式 ICU-18 分母，待临床/质控对照原文确认。
- 颅内感染、脑肿瘤、癫痫、各类脑病、CPR 后及影像异常：编码与检查表尚未映射，一期不宣称覆盖全部，质控只标"本系统当前可识别病例的覆盖情况"。

但实测（del_flag=0 近 30 天）：上述表**全部 0 条；patient_doctor_ecmo_record 全表历史亦为 0 条（最早/最晚时间为空）**。
- **有表结构 ≠ 有数据，这些模块当前未启用。** 二期 ECMO / 导管院感开工前，必须先跨长周期并向信息科确认是否启用、数据是否在他处；不能据此假设可纯读取，必要时仍需设计医生维护记录。字段结构可作为数据模型参考。

## 8. 数据状态模型（采纳实施方案六态）

FOUND / **PARTIAL（有总分但分项或必要字段缺失）** / NOT_RECORDED / UNABLE_TO_ASSESS（CAM 在 RASS -4/-5、GCS 语言 VT、瞳孔无法观察）/ NOT_APPLICABLE（普通患者无 ICP、清醒患者不适用 CPOT）/ UNKNOWN（查询失败）。
- doc join 不到明细、CPOT 缺维度、CAM 缺 RASS 配对等场景使用 PARTIAL/UNKNOWN，不计为正常。

## 10. 可直接进入阶段 1 的结论

- 镇痛镇静页数据源：doc 三表（NRS/CPOT/RASS/CAM，1:1 可直接解析）+ observe.oi_ttpf 仅作趋势镜像补充、不与 doc UNION。
- 神经功能页数据源：doc Z_ICU_GCS（E/V/M、3T）+ observe oi_shenzhi / oi_tkz / oi_tky / oi_lny。
- 查询全部带 patient_id + 时间窗（默认 24h，可 72h/7d/最长 30d），服务端科室权限，区块级六态容错。
- 阈值审批前只做事实、趋势、组合分析与"需核查"提示，不启用硬预警、不判过度镇静/镇痛不足。
