# 第一维度 · 经验性抗感染治疗决策 · 产品设计方案

> 版本：设计稿 v1 · 2026-09-13
> 定位：面向 ICU 疑似感染/脓毒症患者，自动汇总感染证据（诊断、体温、PCT/WBC/CRP/乳酸、培养药敏、抗菌药使用），推理感染部位与多重耐药风险，并给出**经验性抗感染用药方案建议**；医生可采纳/拒绝并留痕，用于用药合理性回溯。

## 一、背景与定位

### 1.1 解决什么问题

| 痛点 | 本模块的解法 |
|---|---|
| 经验性用药靠个人经验，科室差异大 | 按感染部位 × 风险因素输出结构化方案建议 |
| 多重耐药（MDR/MRSA/真菌）风险评估不及时 | 依据**培养药敏 + 休克 + PCT**自动分风险并叠加覆盖建议 |
| 抗菌药是否在「留取培养后」使用无法追溯 | 自动比对微生物送检时间与抗菌药开始时间 |
| 决策过程无留痕，无法做 PDCA | `zing_decision_record` 记录推荐方案 + 医生采纳/拒绝 |

### 1.2 设计原则

1. **只做建议不做医嘱**：输出「推荐方案 + 理由 + 需覆盖的病原体」，最终由医生决定（`decisionStatus`: pending / accepted / declined）；
2. **数据不落库不臆造**：所有证据（PCT、体温、培养）来自 ICU 业务库真实数据，缺失即不展示；
3. **高风险保守覆盖**：感染性休克 / PCT ≥ 2 直接判高风险，建议覆盖 MDR 与 MRSA。

## 三、患者筛选与风险分层

### 3.1 疑似感染患者筛选（`listSuspectPatients`）

数据来源：`patient_info` + `patient_info_diagnosis` + 检验/PCT 等。

筛选口径（按优先级）：

1. 在科患者（`is_in_depart = 1`、`status = 1`、`del_flag = 0`），科室通过 `depart_code` 过滤；
2. **感染相关诊断**：诊断名命中感染/脓毒症关键词（肺炎、脓毒症、感染性休克、尿路感染、腹腔感染、血流感染、导管相关血流感染等）；
3. **感染指标支持**：存在 PCT / WBC / CRP 异常，或存在微生物培养阳性；
4. 补充字段：`pct`、`wbc`、`temperature`、`abxStartTime`（抗菌药最早开始时间）、`shockType`、`riskLevel`。

### 3.2 感染部位推理（`inferInfectionType`）

按诊断名称关键词映射到感染部位；无明确感染部位诊断时：

- 若患者带**休克标记**（`patient_info.is_sepsis_shock` / 诊断含感染性休克）→ 归类为「**脓毒症/感染性休克**」；
- 否则归类为「**感染（部位待明确）**」。

常用映射：肺部/肺炎 → 肺部感染；腹腔/胆道 → 腹腔感染；泌尿 → 尿路感染；血流/导管 → 血流感染；颅内/脑膜 → 中枢感染；皮肤软组织 → 皮肤软组织感染。

### 3.3 休克类型推理（`inferShockType`）

遍历 `patient_info_diagnosis.diag_name`：

| 诊断命中 | 结果 |
|---|---|
| 含「脓毒性休克」 | `shockType = septic`，`septicShock = true` |
| 含「感染性休克」 | `shockType = infectious`，`septicShock = true` |
| 都不命中 | `shockType = none` |

### 3.4 风险分层（`evaluateRisk`）

```
感染性休克(septicShock=true)            → 高风险
PCT ≥ 2.0 ng/mL                         → 高风险
0.5 ≤ PCT < 2.0                         → 中风险
其它（含 PCT 缺失）                      → 低风险
```

> PCT 取患者**最近一次**检验结果；缺失时不升级风险（避免臆造）。

### 3.5 病原体风险增强（`enhanceRiskFromCultures`）

依据微生物培养/药敏结果，覆盖设置 `mrsaRisk / mdrRisk / fungalRisk`：

| 风险 | 触发线索 |
|---|---|
| MRSA | 培养检出金黄色葡萄球菌 / MRSA / 耐甲氧西林；或既往 MRSA 检出史 |
| MDR（多重耐药） | 检出产 ESBL 肠杆菌、CRE、CRPA、CRAB、嗜麦芽窄食单胞菌等；或广谱抗菌药使用 ≥ 一定时长的既往史 |
| 真菌 | 检出念珠菌/曲霉等真菌；或长期广谱抗菌药 + 高危因素 |

> ⚠️ 与第四维度相同的限制：重症库检验结果中通常**只有菌名、没有药敏明细**，因此「MRSA/MDR」判定依赖菌名的**高风险菌种代理规则**（详见 `09-细菌培养检出监测MDRO-产品设计.md` 的边界说明）。

## 四、推荐方案引擎

### 4.1 输出结构

推荐方案以 JSON 字符串写入 `zing_decision_record.recommended_plan`，包含：

- **基础方案（按感染部位）**：首选药物 + 备选药物 + 剂量/频次提示；
- **叠加覆盖项**：`覆盖 MRSA` / `覆盖多重耐药（MDR）` / `覆盖真菌`，每项带**触发理由**（如「PCT 6.2 且检出鲍曼不动杆菌」）；
- **风险提示**：过敏史、肝肾功能（CrCl）提示、需留取培养的提示。

### 4.2 规则优先级

```
最终方案 = 基础方案(感染部位)
          ⊕ 休克/高风险            → 升级为覆盖 MDR 的广谱方案（碳青霉烯类等）
          ⊕ mrsaRisk              → 叠加抗 MRSA 药（万古霉素/利奈唑胺等）
          ⊕ mdrRisk               → 叠加抗 MDR 药（碳青霉烯类/替加环素/多黏菌素等）
          ⊕ fungalRisk            → 叠加抗真菌药（氟康唑/棘白菌素类等）
          ⊖ 过敏史                → 提示排除并给替代
```

### 4.3 采纳留痕

| 字段 | 说明 |
|---|---|
| `recommended_plan` | 系统推荐方案（JSON） |
| `doctor_decision` | 医生最终决策（文本，可为「采纳推荐」或自定义） |
| `decision_status` | `pending` 待处理 / `accepted` 已采纳 / `declined` 已拒绝 |
| `doctor_id / doctor_name` | 决策医生 |
| `infection_type / septic_shock / mrsa_risk / mdr_risk / fungal_risk` | 决策时刻的推理快照（保证历史可回溯） |

> 快照落库是刻意设计：后续知识库调整后，**历史决策仍能还原当时的推理依据**。

## 九、关键实现细节与风险点

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | 无药敏明细，「MRSA/MDR」靠菌名代理 | 与感控口径不一致 | 接入药敏结果后改为真实耐药判定 |
| 2 | PCT 阈值 2.0 / 0.5 为固定值 | 不同人群（免疫抑制、肾功能不全）阈值不同 | 支持科室自定义阈值 |
| 3 | 感染部位推理依赖诊断文本关键词 | 诊断书写不规范时回退「感染（部位待明确）」，方案退化为广谱 | 维护诊断关键词字典，与脓毒症模块共用 |
| 4 | 推荐方案为规则库，不含本院药敏流行率 | 可能与本院实际耐药谱不符 | 引入本院微生物室年度药敏统计作为权重 |
| 5 | 决策快照与知识库版本未绑定 | 知识库更新后无法追溯「当时用的是哪版规则」 | 记录知识库版本号 |
| 6 | 体温/检验取「最新一条」 | 与 APACHE II/SOFA 的「最差值」口径不同 | 明确口径标注 |
| 7 | 所有接口依赖外链签名头 | 内网直连调试会被拒 | 保留一种内网免签的调试通道或文档说明 |

## 十、后续优化建议

1. 接入**本院菌谱与药敏统计**，把经验性方案与本地耐药率联动；
2. 增加**用药后疗效评估**（PCT 变化、体温、白细胞复常）形成闭环；
3. 增加**抗菌药疗程管理**（建议停药/降阶梯提醒）；
4. 与 DDD 模块联动，展示该医生/科室的依从率与 DDD 贡献。
