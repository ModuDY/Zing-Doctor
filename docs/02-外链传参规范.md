# 外链传参打开功能页面规范（含 ICU 系统对接）

> 目标：ICU 信息系统（或任何外部系统）通过一条 URL 免登录打开医生系统的某个功能页面；**所有可外链页面共用一套机制**，新增页面只需注册 + 加路由。
>
> ICU 系统的外链机制：管理员配置一条 URL 模板，模板中用 `${参数名}` 占位，ICU 在跳转时把当前患者/登录人的实际值替换进 URL。**ICU 不做 HMAC 签名计算**，因此医生系统同时支持两种免登录模式（见第 3 节）。

新增可外链页面步骤：
1. `zing_doctor_db_prod.zing_page_config` 插入一行（page_code / frontend_path 唯一）。
2. `frontend/src/router/index.js` 登记同 path 路由。
3. 可选：`application.yml` 的 `allow-page-codes` 配置白名单。

## 2. ICU 外链参数契约（ICU → 医生系统）

医生系统外链入口 `/entry/{pageCode}` 接收并透传 ICU 的以下参数（参数名与 ICU 系统一致，原样使用）：

| ICU 参数名 | 说明 | 医生系统用途 |
|---|---|---|
| `inHospitalNo` | 住院号 | 定位患者（决策页 by-no 接口） |
| `inHospitalHisNo` | HIS 住院号 | 透传 |
| `jzSeries` | 就诊次数 | 透传 |
| `inHospitalSerialNo` | 住院流水号 | 透传 |
| `patientName` | 患者姓名 | 透传/展示 |
| `inDepartTime` | 入科时间 | 透传 |
| `inHospitalTime` | 入院时间 | 透传 |
| `username` | 登录者工号 | 操作人记录 |
| `userId` | 用户 id | 操作人记录 |
| `realname` | 登录者姓名 | 操作人记录（决策留痕默认医生名） |
| `departCode` | 科室 | 透传/后续过滤 |
| `wardCode` | 病区编码 | 透传/后续过滤 |
| `idcard` | 身份证 | 透传 |
| `thirdTicket` / `outSysId` | 第三方登录 ticket / 外部系统 ID | 透传 |
| `token` / `xAccessToken` | ICU 自己的 token | 透传（与医生系统 extToken 不冲突） |

> 定位患者以 `inHospitalNo`（住院号）为准：后端新增接口 `GET /api/antibiotic/patients/by-no/assessment?inHospitalNo=xx`，先在 ICU 库 `patient_info` 按 `in_hospital_no` 解析出患者内部 id，再走完整评估流程。

## 3. 免登录校验（双模式）

### 模式 A：ICU 明文模式（推荐，ICU 系统用）

URL 模板中写死静态密钥 `extToken`（非 `${}` 占位）：

```
GET {doctorBase}/entry/{pageCode}?extToken={静态密钥}&业务参数...
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `extToken` | 是 | 静态密钥，须等于后端配置 `zing.doctor.external-link.icu-token`（默认 `zing-icu-link-token-2026`，生产用环境变量 `ICU_LINK_TOKEN` 注入并改值） |

校验：`extToken` 与配置值常量时间比较，通过即放行；无过期时间。

### 模式 B：签名模式（可动态签名的调用方）

```
GET {doctorBase}/entry/{pageCode}?expire={ts}&sign={hmac}&业务参数...
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `expire` | 是 | 过期时间戳（毫秒），超时拒绝 |
| `sign` | 是 | HMAC-SHA256 签名（hex），密钥 `EXTERNAL_LINK_SECRET` |

签名算法（`sign` 本身不参与）：
```
规范化串 = pageCode={pageCode}&expire={expire}&其余参数按 key 字典序以 k=v 用 & 连接
sign = hex( HmacSHA256( secret, 规范化串 ) )
```

## 4. 跳转与鉴权链路

```
ICU 系统 ──外链URL──▶ 后端 /entry/{pageCode}（extToken 校验 或 验签）
   ├─ 失败：code=401/403/404（JSON）
   └─ 成功：记录访问日志 → 302 → 前端 /page/{pageCode}?pageCode=&extToken=...（或 &expire=&sign=）+ ICU 业务参数
前端捕获外链上下文（sessionStorage）→ 调 /api/** 时带请求头：
   ICU 明文模式：X-External-PageCode / X-External-Token
   签名模式：    X-External-PageCode / X-External-Expire / X-External-Sign
后端 ExternalLinkInterceptor 校验（token 常量比较 或 重算 HMAC）→ 放行，业务参数放 query
```

## 5. ICU 系统外链配置示例

在 ICU 系统的外链配置中新增两条 URL 模板（把 `{doctorBase}` 换成医生系统实际地址，如 `http://100.120.1.104:2001`，`extToken` 固定写死）：

**示例 1：打开疑似感染患者列表（带入登录人/科室）**
```
{doctorBase}/entry/abx-patient-list?extToken=zing-icu-link-token-2026&username=${username}&userId=${userId}&realname=${realname}&departCode=${departCode}&wardCode=${wardCode}
```

**示例 2：直接打开某患者经验性抗感染决策页**
```
{doctorBase}/entry/abx-decision?extToken=zing-icu-link-token-2026&inHospitalNo=${inHospitalNo}&inHospitalHisNo=${inHospitalHisNo}&jzSeries=${jzSeries}&patientName=${patientName}&username=${username}&realname=${realname}&departCode=${departCode}&wardCode=${wardCode}
```

> ICU 替换 `${...}` 后得到的 URL 即为最终访问地址；`extToken` 是固定值不参与替换。

## 6. 联调辅助

本地开发时可调用签发接口快速生成**签名模式**外链：

```
GET http://localhost:8081/api/external/token?pageCode=abx-decision&baseUrl=http://localhost:5173&patientId=P1001
```

返回完整可点击的外链 URL（含签名）。生产环境签发方应为 ICU 系统或医生系统管理端，不要暴露给浏览器端随意签发。

ICU 明文模式联调：直接访问 `{doctorBase}/entry/abx-decision?extToken={配置值}&inHospitalNo=xx` 即可，无需签发。

## 7. 安全说明

- ICU 明文模式（extToken）依赖：**内网环境 + 静态密钥 + 必带患者/用户标识**。密钥泄露风险在内网可控，适合 P0；如后续要求更高安全，可升级为「IP 白名单 + token」或让 ICU 支持 HMAC 签名（模式 B）。
- 生产部署必须通过环境变量修改默认值：`EXTERNAL_LINK_SECRET`（签名密钥）、`ICU_LINK_TOKEN`（ICU 明文密钥）。
